# 하위 세션을 시작할 수 없을 때 (roadmap-teammate 3절)

`start_session`으로 하위 세션을 시작할 수 없을 때, 하위 세션이 끝난 알림 턴에서 다음 단계를 시작할 때 읽는다. 절 번호(0절, 1절 등)는 [../SKILL.md](../SKILL.md)의 절이다.

| 경우 | 알아보는 법 | 읽을 절 |
|---|---|---|
| 세션 도구가 아예 없음 | 터미널 CLI, 웹처럼 `start_session`이 도구 목록에도 `ToolSearch`에도 없다 | "세션 도구가 아예 없는 곳" |
| 앱이 시작을 막음 | `start_session`은 있는데 앱이 새 세션 시작을 막는다(휴대폰 Remote Control에서 보낸 말로 시작한 턴, 자동 알림 턴 등) | "앱이 시작을 막으면" |
| 하위 세션이 끝난 알림 턴 | `<side-sessions-event>` 메시지로 시작한 턴 | "자동 이벤트 턴" |

- 도구 목록에 이름만 있으면(deferred) 없는 것이 아니다. 먼저 `ToolSearch`로 `select:mcp__ccd_session__start_session`을 불러온다. 이름만 있는 걸 안 보인다고 여겨 `Agent`로 대신하지 않는다.
- 두 경우는 다르다. 세션 도구가 아예 없는 곳에서만 `Agent`로 대신한다. 앱이 시작을 막으면 `Agent`로 대신하지 않는다.

## 세션 도구가 아예 없는 곳

터미널 CLI, 웹처럼 `start_session`이 목록에도 `ToolSearch`에도 없을 때 이렇게 한다. 앱이 시작을 막은 경우(아래)와는 다르다.

1. 코드를 바꾸는 일은 `Agent`에 `isolation: "worktree"`로 맡긴다. 브리프는 2절 꼴 그대로, PR은 13절 그대로다(하위 에이전트가 자기 브랜치에 커밋·push하고 PR을 만든다). 같은 파일을 건드리는 일은 차례로, 겹치지 않는 일은 함께 돌린다.
2. 하위 에이전트는 결과를 이번 턴에 돌려주고 끝난다. 마일스톤 세션에 이어 맡기기(1절)는 할 수 없으니, 줄마다 새로 맡기고 브리프에 앞 줄의 결과(PR 번호, 바뀐 것)를 요약해 넣는다.
3. `Agent`도 없으면 부모가 1절 순서대로 직접 하나씩 하고, 줄마다 브랜치·PR은 그대로 지킨다.

- 시작 보고 첫 줄에 "세션 도구가 없어 하위 에이전트(또는 직접)로 진행"이라고 적는다.
- 브랜치·PR로 끝나는 구현 작업을 `Agent`에 맡기는 것은 이 경우뿐이다(3절).

## 앱이 시작을 막으면

휴대폰(Remote Control)에서 보낸 말로 시작한 턴이면 앱이 새 세션 시작을 막을 수 있다. Remote Control은 `Agent`로 바꿀 이유가 아니다. **앱이 시작을 막으면 `Agent`로 대신하지 않는다.** 차례대로 한다.

1. **기존 하위 세션에 맡긴다.** 새 세션이 막혀도 이미 있는 세션에 보내는 것은 된다.
   - 고르기: 쉬고 있는(idle) 기존 하위 세션 가운데 내용이 맞거나 이미 끝난 세션. 마일스톤 일이면 **같은 마일스톤 세션만**, 없으면 2번으로.
   - 찾기: `mcp__ccd_session_mgmt__list_sessions` `{"linked": true}`.
   - 보내기: `SendMessage`로 다음 일을 맡긴다(브리프는 2절 꼴 그대로).
   - 그 세션의 작업 폴더·브랜치가 다음 일과 다르면 브리프에 "기본 브랜치에서 새 브랜치(또는 새 worktree)를 만들어 일할 것"을 적는다(worktree 개수는 13절).
   - 긴 세션은 앞부분이 요약되며 이어진다. 앞 일의 맥락에 기대지 말고 필요한 사실을 브리프에 다 적는다.
2. **그래도 안 되면** 지금처럼 한다.
   - 부모가 몇 번의 도구 호출로 끝낼 일이면 알리고 여기서 직접 한다(1절).
   - 아니면 다음 작업을 `own_initiative` 카드로 남기고, 보고에 "다음 작업은 카드를 누르거나 '이어 해줘'라고 하면 시작" 한 줄을 적는다.
   - 자리 비움(10절) 중이면 "돌아오시면 정할 것"에 모은다.

- 맡길 세션이 남아 있어야 1번이 된다. 머지 뒤 정리에서 다음 일이 남았으면 하위 세션 하나는 다음 일을 맡긴 뒤에 정리한다([pr-merge.md](pr-merge.md)의 머지 뒤 정리, "맡길 세션 하나는 남긴다").

## 자동 이벤트 턴

- 하위 세션이 끝난 알림(`<side-sessions-event>`) 턴에서 사용자가 이미 맡긴 다음 단계는 그대로 하위 세션으로 시작한다(앱이 허용하는 경우). 앱이 막으면 위 "앱이 시작을 막으면"대로 한다.
- 이 턴은 사용자가 자리에 없을 수 있다. 묻지 말고 이전 답을 쓴다. 이전 답이 없으면 그 질문은 보고에 남긴다(0절 "묻지 않을 때").
