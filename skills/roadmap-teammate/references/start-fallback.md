# 하위 세션을 시작할 수 없을 때 (roadmap-teammate 3절)

`start_session`으로 새 하위 세션을 만들 수 없을 때, 하위 세션이 끝난 알림 턴에서 다음 단계를 시작할 때 읽는다. 절 번호(0절, 1절 등)는 [../SKILL.md](../SKILL.md)의 절이다.

## 정말 못 만드는지 먼저 본다

- 도구 목록에 이름만 있으면(deferred) 없는 것이 아니다. 먼저 `ToolSearch`로 `select:mcp__ccd_session__start_session`을 불러온다. 이름만 있는 걸 안 보인다고 여겨 건너뛰지 않는다.
- 못 만드는 경우는 둘이고, 둘 다 아래 사다리 하나로 한다.

| 경우 | 알아보는 법 |
|---|---|
| 세션 도구가 아예 없음 | 터미널 CLI, 웹처럼 `start_session`이 도구 목록에도 `ToolSearch`에도 없다 |
| 앱이 시작을 막음 | `start_session`은 있는데 앱이 새 세션 시작을 막는다(휴대폰 Remote Control에서 보낸 말로 시작한 턴, 자동 알림 턴 등) |

## 사다리: 세션 도구가 없거나 앱이 시작을 막으면

차례로 해 보고 되는 첫 길로 간다. 어느 길이든 한 일 = 브랜치 하나 = PR 하나(13절), 브리프 꼴(2절), 0절 권한은 그대로다.

1. **쉬고 있는 기존 하위 세션에 맡긴다.** 새 세션이 막혀도 이미 있는 세션에 보내는 것은 된다. 세션 도구가 아예 없으면 기존 세션도 없으니 2번으로 간다.
   - 고르기: 쉬고 있는(idle) 기존 하위 세션 가운데 내용이 맞거나 이미 끝난 세션. 마일스톤 일이면 **같은 마일스톤 세션만**, 없으면 2번으로.
   - 찾기: `mcp__ccd_session_mgmt__list_sessions` `{"linked": true}`.
   - 보내기: `SendMessage`로 다음 일을 맡긴다(브리프는 2절 꼴 그대로).
   - 그 세션의 작업 폴더·브랜치가 다음 일과 다르면 브리프에 "기본 브랜치에서 새 브랜치(또는 새 worktree)를 만들어 일할 것"을 적는다(동시에 돌리는 기준은 13절).
   - 긴 세션은 앞부분이 요약되며 이어진다. 앞 일의 맥락에 기대지 말고 필요한 사실을 브리프에 다 적는다.
2. **`Agent`에 `isolation: "worktree"`로 맡긴다.**
   - 브리프는 2절 꼴 그대로, PR은 13절 그대로다(하위 에이전트가 자기 브랜치에 커밋·push하고 PR을 만든다).
   - 같은 파일을 건드리는 일은 차례로, 겹치지 않는 일은 함께 돌린다.
   - 하위 에이전트는 결과를 이번 턴에 돌려주고 끝난다. 마일스톤 세션에 이어 맡기기(1절)는 할 수 없으니, 줄마다 새로 맡기고 브리프에 앞 줄의 결과(PR 번호, 바뀐 것)를 요약해 넣는다.
   - 돌아온 PR은 하위 세션의 PR처럼 5절대로 확인한다.
3. **부모가 직접 한다.** `Agent`도 없거나 쓸 수 없으면 1절 순서대로 하나씩 한다. 줄마다 기본 브랜치에서 새 브랜치를 만들어 PR을 따로 낸다.

- 시작 보고 첫 줄에 어느 길로 갔는지 적는다(예: "새 세션이 막혀 기존 세션 [M2 …]에 맡김", "세션 도구가 없어 하위 에이전트로 진행", "직접 진행").
- 자리 비움(10절) 중에도 사다리를 타고 계속한다. 시작이 막혔다는 이유로 "돌아오시면 정할 것"에 미루지 않는다. 0절 권한을 받지 않은 일만 미룬다.
- 쉬는 하위 세션이 모두 보관됐으면 1번을 건너뛰고 2번으로 간다. 세션을 남겨 두려고 정리를 미루지 않는다.

## 자동 이벤트 턴

- 하위 세션이 끝난 알림(`<side-sessions-event>`) 턴에서 사용자가 이미 맡긴 다음 단계는 그대로 하위 세션으로 시작한다(앱이 허용하는 경우). 앱이 막으면 위 사다리대로 한다.
- 이 턴은 사용자가 자리에 없을 수 있다. 묻지 말고 이전 답을 쓴다. 이전 답이 없으면 그 질문은 보고에 남긴다(0절 "묻지 않을 때").
