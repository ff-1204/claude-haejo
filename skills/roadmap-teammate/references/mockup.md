# 시안 먼저 (roadmap-teammate 2절)

일을 맡기기 전에 시안을 보이고 확정받을 때, 마무리에서 시안과 대조할 때 읽는다. 절 번호(0절, 5절 등)는 [../SKILL.md](../SKILL.md)의 절이다.

흐름: 요청 → 시안 → 사용자 검토·수정 → 확정 → 만들기 → 시안대로 됐는지 확인.

## 언제 만드나

| 만든다 | 만들지 않는다 |
|---|---|
| 사용자가 보거나 정하는 결과가 있는 일: 새 기능, 화면·문구·흐름, 문서 구조나 규칙을 바꾸는 일, 여러 PR에 걸친 일 | 1절 "작은 일은 부모가 직접"에 드는 일 |
| | 버그 고침처럼 바른 결과가 하나뿐인 일 |
| | 사용자가 "시안 없이"라고 한 일 |
| | 이미 확정된 기획 문서(roadmap 세부 항목의 "끝났다고 보는 것")가 시안 구실을 하는 일 |

## 시안의 꼴

- "지금 ↔ 시안"을 나란히 보이는 단순한 꼴이다. 항목마다 한 줄, 번호를 붙인다(`A1`, `A2` …).
- 화면이면 실제 화면(스크린샷)을 바탕으로 만든다. 색·모양처럼 디자인이 필요하면 [projects.md](projects.md) "공통"의 디자인 안 2~3개를 따른다.
- 휴대폰에서 한 화면에 읽히게 짧게 쓴다.
- Claude가 추천으로 정한 것은 "추천대로 정한 것"으로 표시한다.
- 사용자 취향인 결정(7절: 화면 문구, 보상·답례, 처음 흐름, 이름 붙이기)은 시안 항목으로 넣고, 문구면 실제 문장을 쓴다. 시안 확정이 곧 그 답이다.

```
**시안: 저장 화면**
| | 지금 | 시안 |
|---|---|---|
| A1 | 저장 버튼 없음 | 오른쪽 위에 "저장" 버튼 |
| A2 | 저장 뒤 아무 표시 없음 | "저장했어요" 2초 표시 (추천대로 정한 것) |
| A3 | — | 저장 실패 시 "다시 시도" 버튼 |
```

## 검토·수정과 확정

- 시안을 보인 뒤 선택 UI로 묻는다: 이대로 진행(추천) / 고칠 곳 있음.
- 고치자고 하면 고친 시안을 다시 보이고, "이대로"라고 할 때까지 되풀이한다. 번호는 바꾸지 않는다(빠진 항목은 "(뺌)", 새 항목은 다음 번호).
- 확정 전에는 구현을 시작하지 않는다.

## 확정된 시안이 기준

- 브리프 "할 일·끝난 모습"(2절)에 확정 시안의 항목을 번호째 그대로 옮긴다.
- 하위 세션은 시안에 없는 것을 더하지 않는다. 시안대로 못 하는 항목은 다르게 만들지 말고 이유와 함께 보고한다.
- 진행 중 시안이 바뀌어야 하면 부모가 사용자에게 다시 확인받는다. 자리 비움 중이면 그 항목을 "돌아오시면 정할 것"에 두고 나머지를 계속한다.
- 시안 뒤에 새로 생긴 취향 결정만 7절대로 따로 묻는다.

## 마무리 확인 = 시안 대조

- 끝나면 부모가 시안 항목마다 "됐음 / 안 됨 / 다르게 됨(이유)"을 표로 보인다. 화면이면 스크린샷을 함께 본다.
- 사용자에게 가는 마무리 보고는 이 표가 중심이다([wrap-up.md](wrap-up.md) "돌아오셨을 때 보고").
- 5절 PR 확인 4개와 위험한 PR 검토는 머지 전 기술 확인으로 그대로 한다. 시안 대조가 대신하지 않는다.

```
| 항목 | 결과 |
|---|---|
| A1 저장 버튼 | 됐음 |
| A2 "저장했어요" 표시 | 됐음 |
| A3 다시 시도 버튼 | 다르게 됨: 버튼을 아래쪽에 (진행 중 사용자 확인 받음) |
```

## 자리 비움

- 떠나기 전에 시안을 확정받는다([wrap-up.md](wrap-up.md) "자리 비움").
- 확정받지 못한 일은 시작하지 않고 "돌아오시면 정할 것"에 둔다.
