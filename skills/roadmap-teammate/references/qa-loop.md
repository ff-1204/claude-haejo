# 테스트 > 개선 > 커밋 반복 (QA 루프)

목표는 마일스톤 체크가 아니라 "하나의 완성된 프로젝트"다. 천천히 꼼꼼하게 한다. 사용자가 시간(예: 6시간)을 주면 그 안에서 반복한다.

## 0. 준비 (부모)

1. 테스트케이스를 먼저 기획한다.
   - 기준: 페르소나·시나리오, 체크리스트의 ✅ 항목, 지난 회차에 고친 것.
   - 케이스마다 번호, 단계, 기대 결과를 적는다.
2. 개발 공간과 테스트 공간을 나눈다.
   - 기본: 개발용 worktree와 테스트용 worktree(테스트할 커밋에 고정)를 따로 둔다. 개발 서버가 있으면 포트도 나눈다.
   - 한 번에 하나만 돌 수 있는 도구가 있으면(예: Unity 배치) 나누지 말고 세션을 하나씩 순서대로 돌린다.
   - 프로젝트별 설정은 [projects.md](projects.md)를 본다.
3. 회차 기록 위치를 정한다. 프로젝트에 정해진 곳이 있으면 그곳([projects.md](projects.md)), 없으면 저장소의 `qa-reports/round-NN.md`에 둔다.
   - 테스트 세션은 보고서를 테스트용 worktree가 아니라 기본 사본의 기록 위치(또는 저장소 밖)에 쓰고 커밋하지 않는다. 다음 개선 세션이 그 보고서를 자기 PR에 함께 담는다(0절 권한이 있을 때). 개선 세션이 없이 멈추면 부모가 마무리 때 커밋 권한대로 처리한다.

## 1. 테스트 회차 (매번 새 세션, SKILL.md 0절에서 정한 테스트 모델)

- 테스트 세션은 **코드를 고치지 않는다.** 케이스를 수행하고 보고서만 쓴다.
- 받는 것: 케이스 목록, 지난 회차에 고친 것 목록. **이전 보고서는 주지 않는다**(편향 방지).
- 테스터 관점으로 판단한다.
  - 잘된 것
  - 고칠 것: 버그, 막히는 흐름
  - UI/UX/디자인 개선점
- 0절에서 컴퓨터 사용을 허락받았으면 실제로 실행해 본다(예: 처음 10분, 주요 메뉴 흐름). 허락받지 않았으면 자동 테스트·스크린샷·브라우저 미리보기로 대신한다.
- 결과는 심각도별로 나눈다: 꼭 고칠 것 / 고치면 좋은 것 / 기획 결정 필요.

## 2. 개선 회차 (새 세션, 0절에서 정한 구현 모델)

- 꼭 고칠 것 → 고치면 좋은 것 순서로 고친다.
- 기획 결정이 필요한 것은 비슷한 제품을 조사해 이 프로젝트에 맞는 쪽으로 정하고, 체크리스트에 기록한다.
- 남는 시간에는 체크리스트의 남은 항목을 개발한다. 확인이 필요하거나 어려운 것은 후순위로 둔다.
- 확인은 프로젝트 규칙([projects.md](projects.md), 프로젝트 CLAUDE.md)을 따른다. 정해진 게 없으면 SKILL.md 5절 "PR에서 돌릴 테스트"대로 PR마다 그 고침에 닿는 테스트만 돌리고(형식·버전 번호를 바꿨으면 그 번호를 확인하는 테스트도, 저장·네트워크 같은 공통 코드를 바꿨으면 전체를), CI는 그대로 기다린다. 전체 테스트는 마일스톤 끝이나 루프를 멈출 때 기본 브랜치에서 한 번 돌린다([wrap-up.md](wrap-up.md) "마무리" 3). PR 본문에 돌린 테스트와 돌리지 않은 범위를 적는다.
- 커밋·PR은 SKILL.md 0절 권한 답대로만 한다(권한이 있으면 자기 브랜치에 목적별 커밋(메시지는 SKILL.md 13절 꼴), PR 하나). 지난 회차 보고서 파일을 이 PR에 함께 커밋한다. 머지는 부모가 한다(SKILL.md 13절). push가 공개 배포인 저장소는 테스트 통과 후에만, 그것도 권한이 있을 때만 머지한다.

## 3. 다음 회차

- 부모가 PR 확인 항목을 보고(SKILL.md 5절) 0절 권한대로 머지한다. 그다음 머지된 기본 브랜치로 새 테스트 세션을 만든다. 앱이 세션 시작을 막으면 SKILL.md 3절대로 한다(`Agent`로 대신하지 않는다).
- 머지까지 맡기지 않았으면 회차마다 머지를 기다리지 않는다. 다음 테스트 회차는 그 PR 브랜치에서 하고, 다음 개선 세션은 같은 브랜치·같은 PR에 커밋을 더한다(본문 갱신). 머지는 사용자에게 물어 한 번 한다.
- 회차 제목 예: "QA 9회차: 이웃에게 선물·편지 + 회귀"
- 회귀 케이스(지난 회차에 고친 것)는 매 회차 포함한다.

## 멈추는 때

- 0절에서 정한 시간이 다 됐거나 끝내는 기준을 채웠을 때
- 두 회차 연속 꼭 고칠 것이 없고, 남은 체크리스트 항목이 모두 확인 필요·어려움·사용자 항목일 때
- 결제나 되돌리기 어려운 결정이 필요할 때 → 그것만 사용자에게 남기고, 나머지는 계속한다
