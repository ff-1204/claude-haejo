# 마무리와 자리 비움

## 자리 비움

사용자가 "병원 다녀올게", "자러 갈게", "다되면 마무리해줘", "다른 PC에서 이어 할게"처럼 자리를 비운다고 하면 이 방식으로 바꾼다.

- **떠나기 전에 한 번만 묻는다.** 사용자가 자리를 비운다고 말한 그 차례(아직 자리에 있을 때)에 커밋·push·태그 권한을 선택 UI로 묻는다(SKILL.md 0절). 이미 이번 실행에서 받은 답이 있으면 그대로 쓴다.
- **그 뒤로는 묻지 않는다.** 선택 UI(`AskUserQuestion`)를 부르지 않는다. 답을 기다리는 동안 일이 멈추기 때문이다. 권한을 받지 않은 커밋·push·태그는 하지 않고 "돌아오시면 정할 것"에 둔다.
- 결정이 필요한 것은 두 가지로 나눈다.
  - 되돌릴 수 있고 비슷한 제품·프로젝트 규칙으로 판단할 수 있는 것: 추천대로 정하고 "추천대로 정한 것"에 적는다.
  - 결제, 계정, 공개 전환, 지우기처럼 되돌리기 어려운 것: 하지 않고 "돌아오시면 정할 것"에 모은다. 그 일에 기대는 작업만 멈추고 나머지는 계속한다.
- PC가 잠들면 세션도 멈춘다. 앱의 깨어 있기(keep awake)를 켤 수 있으면 켜고, 못 켜면 보고에 적는다.
- 맡은 일이 다 끝나면 아래 "마무리"를 하고 멈춘다. 새 일을 스스로 시작하지 않는다.

## 마무리

사용자가 "다되면 문서 정리하고 마무리해줘"라고 했거나, 자리 비움 중 맡은 일이 다 끝났거나, 마일스톤이 끝났을 때 한다. 순서대로:

1. **전체 확인**: 프로젝트의 전체 테스트를 한 번 돌리고, 하위 세션들의 커밋이 모두 들어왔는지 본다(`git log`, `git status -sb`). 진행 중인 하위 세션이 있으면 끝날 때까지 기다린다.
2. **배포·태그**: 0절 권한 답대로만. 권한이 없으면 하지 않고, 사용자가 자리에 있으면 선택 UI로 묻고, 없으면 "돌아오시면 정할 것"에 "push·태그 vX.Y.Z"로 둔다. push가 공개 배포인 저장소는 테스트가 통과한 뒤에만.
   - **덜 끝난 마일스톤**(막힌 항목이 남음): 태그와 끝 표시를 하지 않는다. 끝난 줄만 체크리스트 ✅와 시나리오 갱신을 하고, 남은 줄은 "돌아오시면 정할 것"과 이어 적는다.
3. **문서 정리**: 이번에 바뀐 것을 아래 문서에 맞춘다. 있는 문서만.
   - README(사용법·기능 목록이 바뀌었으면)
   - 개발 문서(`docs/개발.md`, CLAUDE.md 같은 개발자용 안내)
   - 체크리스트(✅ 표시, 날짜, 새로 생긴 🆕)
   - 기획 문서(roadmap 스킬을 쓴 프로젝트면 갱신 플로우: 끝 표시 → 시나리오 → 점수)
   - QA 기록(테스트 회차를 돌렸으면)
4. **메모리**: 다음 세션이 알아야 할 결정·규칙·주의점을 메모리에 남긴다(이미 있으면 고친다).
5. **이어 하기 메모**: 메모리는 PC마다 따로라 다른 기기로 넘어가지 않는다. 저장소 안 개발 문서(없으면 `docs/이어하기.md`)에 "지금 상태 · 마지막 태그 · 진행 중이던 것 · 다음 할 일 · 사용자 몫 · 다른 PC 준비(스킬 설치, `projects.local.md` 옮기기)"를 짧게 적는다. 커밋은 권한이 있을 때만. 공개 저장소면 roadmap rules.md "공개 저장소"대로 내부 경로·비공개 저장소 이름을 뺀다.
   - **사용자가 다른 PC를 말했으면 커밋만으로는 안 된다.** 다른 PC는 원격에서만 받을 수 있다. 배포가 아닌 브랜치(예: `wip/이어하기`)에 이어 하기 메모와 진행 중 브랜치(하위 세션 worktree 브랜치 포함)를 push해야 한다. 이 push도 사용자 권한이니, 사용자가 떠나기 전에 선택 UI로 "wip 브랜치에 커밋·push할까요?"를 묻는다. main push가 곧 배포인 저장소에서 덜 된 작업을 main에 올리지 않는다. push를 못 하면 보고 첫 줄에 "이 PC에만 있음"과 이유를 적는다.
6. **하위 세션 정리**: 끝난 하위 세션은 보관(archive)해도 되는지 보고에 적는다(사용자가 답하면 한다).
