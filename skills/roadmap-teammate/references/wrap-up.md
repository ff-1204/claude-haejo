# 마무리와 자리 비움

## 자리 비움

사용자가 "병원 다녀올게", "자러 갈게", "다되면 마무리해줘", "다른 PC에서 이어 할게"처럼 자리를 비운다고 하면 이 방식으로 바꾼다.

- **떠나기 전에 한 번만, 한 화면에 묶어 묻는다.** 사용자가 자리를 비운다고 말한 그 차례(아직 자리에 있을 때), 사용자가 "미리 물어볼 거 있니?"라고 묻지 않아도 아래를 한 번의 선택 UI로 묻는다. 이미 이 세션에서 받은 답은 빼고 묻는다(SKILL.md 0절).
  1. 커밋·push·PR·머지 권한(남은 일이 머지까지 가면 "머지까지 맡기기"도 선택지에)
  2. 남은 일 중 사용자가 정해야 할 것(취향·미루기·외부 서비스). 정할 게 없으면 묻지 않는다.
  3. 확인 창이 뜰 만한 명령(허락 목록에 없는 명령, 지우기, 새 도구 설치)이 남은 일에 있으면 미리 허락받거나 허락 목록에 넣을지
  4. 깨어 있기(keep awake)·컴퓨터 사용 허락이 필요한지
  - 물은 뒤에는 "더 물을 것 없어요. <예상 시간> 뒤 끝날 것 같아요"처럼 더 물을 게 없다는 것과 예상 시간을 분명히 말한다.
- **그 뒤로는 묻지 않는다.** 선택 UI(`AskUserQuestion`)를 부르지 않는다. 답을 기다리는 동안 일이 멈추기 때문이다. 권한을 받지 않은 일은 하지 않고 "돌아오시면 정할 것"에 둔다.
- **머지**: 0절에서 머지까지 맡겼으면 확인 항목 4개(위험한 PR은 검토까지, SKILL.md 5절)를 통과한 PR을 하나씩 머지한다. 아니면 머지하지 않고 "돌아오시면 정할 것"에 PR 링크를 모은다. 이때도 PR마다 SKILL.md 13절 "보고 꼴"(선택지 빼고)로 적는다. 서로 기대는 작업(SKILL.md 13절)은 앞 PR이 머지되지 않으면 멈춘다. main push가 곧 배포인 저장소는 자리 비움 중 머지하지 않고 "돌아오시면 정할 것"에 둔다.
- 결정이 필요한 것은 두 가지로 나눈다.
  - 되돌릴 수 있고 비슷한 제품·프로젝트 규칙으로 판단할 수 있는 것: 추천대로 정하고 "추천대로 정한 것"에 적는다.
  - 그중 **사용자 취향인 것**(제품을 쓰는 사람이 보는 문구·보상·처음 흐름, 핵심 경험): 추천대로 하되 보고 맨 위 "확인해 주세요"에 바꾼 문장·내용을 그대로 보인다(SKILL.md 7절).
  - 외부 서비스를 바꾸는 것: 하지 않고 그 줄을 ⏸로 둔다.
  - 결제, 계정, 공개 전환, 지우기처럼 되돌리기 어려운 것: 하지 않고 "돌아오시면 정할 것"에 모은다. 그 일에 기대는 작업만 멈추고 나머지는 계속한다.
- 다음 하위 세션 시작이 앱에서 막히면 `Agent`로 대신하지 않는다. 먼저 쉬고 있는 기존 하위 세션에 `SendMessage`로 맡기고, 그것도 안 되면 그 작업을 "돌아오시면 정할 것"에 모은다(SKILL.md 3절).
- PC가 잠들면 세션도 멈춘다. 앱의 깨어 있기(keep awake)를 켤 수 있으면 켜고, 못 켜면 보고에 적는다.
- 맡은 일이 다 끝나면 아래 "마무리"를 하고 멈춘다. 새 일을 스스로 시작하지 않는다(SKILL.md 0절 '개발 범위'에서 더 맡긴 만큼은 이어 한다).

## 마무리

사용자가 "다되면 문서 정리하고 마무리해줘"라고 했거나, 자리 비움 중 맡은 일이 다 끝났거나, 마일스톤이 끝났을 때 한다. 순서대로:

1. **PR 상태 확인**: 하위 세션들의 PR이 모두 있는지·머지됐는지 본다(`gh pr list`, 원격이 없으면 `git log`, `git status -sb`). 진행 중인 하위 세션이 있으면 끝날 때까지 기다린다.
2. **머지**: 0절 권한 답대로만(SKILL.md 13절). 권한이 없으면 하지 않고, 사용자가 자리에 있으면 선택 UI로 묻고, 없으면 "돌아오시면 정할 것"에 "PR 머지 <링크들>"로 둔다. main push가 곧 배포인 저장소는 자리 비움 중 머지하지 않고 "돌아오시면 정할 것"에 둔다. 태그는 사용자가 요청했을 때만 머지 뒤에 단다.
   - **덜 끝난 마일스톤**(막힌 항목이 남음): 태그와 끝 표시를 하지 않는다. 끝난 줄만 체크리스트 ✅와 시나리오 갱신을 하고, 남은 줄은 "돌아오시면 정할 것"과 이어 적는다.
3. **전체 테스트**: 머지된 기본 브랜치에서 프로젝트의 전체 테스트를 한 번 돌린다. PR마다는 관련 테스트만 돌렸으니(SKILL.md 5절) 여기가 전체 테스트 자리다.
   - 깨진 것은 고침 PR(하위 세션)로 만든다.
   - 함께 돌릴 때만 흔들리는 테스트는 이때 "정해진 시간 기다리기"를 "조건 기다리기"로 고친다(같은 고침 PR이나 따로 PR).
   - 머지된 worktree가 남아 있으면 지운다(SKILL.md 13절).
   - 머지 권한이 없어 머지를 못 했으면 전체 테스트도 "돌아오시면 정할 것"에 "PR 머지 뒤 전체 테스트"로 둔다.
4. **문서 정리**: 이번에 바뀐 것을 아래 문서에 맞춘다. 있는 문서만.
   - README(사용법·기능 목록이 바뀌었으면)
   - 개발 문서(`docs/개발.md`, CLAUDE.md 같은 개발자용 안내)
   - 체크리스트(✅ 표시, 날짜, 새로 생긴 🆕)
   - 기획 문서(roadmap 스킬을 쓴 프로젝트면 갱신 플로우: 끝 표시 → 시나리오 → 점수)
   - QA 기록(테스트 회차를 돌렸으면)
5. **메모리**: 다음 세션이 알아야 할 결정·규칙·주의점을 메모리에 남긴다(이미 있으면 고친다).
6. **이어 하기 메모**: 메모리는 PC마다 따로라 다른 기기로 넘어가지 않는다. 저장소 안 개발 문서(없으면 `docs/이어하기.md`)에 "지금 상태 · 마지막 태그 · 진행 중이던 것 · 다음 할 일 · 사용자 몫 · 다른 PC 준비(스킬 설치, `projects.local.md` 옮기기)"를 짧게 적는다. 커밋은 권한이 있을 때만. 공개 저장소면 roadmap rules.md "공개 저장소"대로 내부 경로·비공개 저장소 이름을 뺀다.
   - **다른 PC 준비는 마일스톤마다 확인한다.** 사용자가 말하지 않아도, "새 PC에서 저장소를 클론하고 문서대로 하면 이어 할 수 있나"를 본다: 준비 문서의 설치·설정 단계가 지금 코드와 맞는지, 이 PC에만 있는 파일(설정, 비밀값 자리, 개인 규칙)이 무엇이고 어떻게 옮기는지 적혀 있는지, 옛 내용이라 헷갈릴 문서가 남아 있지 않은지. 어긋난 것은 문서 정리(4)에서 고친다. 애매한 문서를 지울지는 사용자에게 묻는다.
   - **사용자가 다른 PC를 말했으면 커밋만으로는 안 된다.** 다른 PC는 원격에서만 받을 수 있다. 배포가 아닌 브랜치(예: `wip/이어하기`)에 이어 하기 메모와 진행 중 브랜치(하위 세션 worktree 브랜치 중 아직 PR로 push되지 않은 것)를 push해야 한다. 이 push도 SKILL.md 0절 권한이니, 사용자가 떠나기 전에 선택 UI로 "wip 브랜치에 커밋·push할까요?"를 묻는다. main push가 곧 배포인 저장소에서 덜 된 작업을 main에 올리지 않는다. push를 못 하면 보고 첫 줄에 "이 PC에만 있음"과 이유를 적는다.
7. **하위 세션 정리**: PR이 머지된 하위 세션은 사용자가 고른 "1.삭제 / 2.보관 / 3.그대로 둠"대로 한다(SKILL.md 13절 "머지 뒤 정리"). 답을 못 받았으면 정리하지 않고 "돌아오시면 정할 것"에 둔다. 머지되지 않은 PR의 세션과 PR이 없는 세션은 정리할지 보고에 적는다(사용자가 답하면 한다).
8. **정리 후보 보이기**: 지우지는 않고 목록만 보인다. 머지된 worktree·로컬 브랜치, 끝난 하위 세션, 계획이 바뀌어 안 쓰게 된 대기 세션(SKILL.md 1절), 이번 작업에서 만들고 이제 안 쓰는 폴더·파일(임시 검사 폴더, 옛 저장소 사본, 내려받은 압축 파일), 크기가 큰 폴더(빌드 결과·캐시, 용량과 함께). 각 줄에 "왜 지워도 되는지"와 "지우면 되돌릴 수 있는지"를 적고, 선택 UI로 고르게 한 뒤 고른 것만 지운다. 저장소에 커밋되지 않은 변경이 있는 폴더는 후보에 넣지 않고 따로 알린다.
9. **부모 세션 넘기기**: 마일스톤이 끝났거나 이 부모 대화의 앞부분이 요약되기 시작했으면, 다음 마일스톤은 새 부모 세션에서 한다. 6의 이어 하기 메모를 최신으로 고친 뒤, `start_session` `own_initiative` 카드로 "M3 이어 하기"처럼 새 세션을 제안한다. 브리프에는 이어 하기 메모 경로, 0절에서 받은 답(권한·꼬리표·모델·범위), 열린 PR과 쉬는 하위 세션 목록만 적는다. 카드를 누를지는 사용자가 정한다. 자리 비움 중이면 카드만 남기고 "돌아오시면 정할 것" 1번에 둔다.

## 돌아오셨을 때 보고

휴대폰에서 한 화면에 읽히게 쓴다.

```
**한 것**: M2 7개 끝, PR 7개 머지, v0.17.0 배포 (세션 링크들)
**확인**: 전체 테스트 통과 · 휴대폰 화면 확인
**확인해 주세요**: 1) 첫걸음 문구 "…" → "…" (추천대로 바꿈) 2) …
**추천대로 정한 것**: 1) … 2) …
**돌아오시면 정할 것**: 1) PR 머지 (PR 링크들) 2) … (왜 사용자 몫인지)
**사용자 몫**: T1 두 속도로 며칠 놀아 보기
**다음**: 1. M3 시작 (추천) 2. …
```
