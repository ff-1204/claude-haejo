# 외부 준비와 비밀값

## 사용자가 바깥에서 해야 하는 준비

로그인, 클라우드 저장, 결제, 지도, 알림처럼 외부 서비스가 필요한 작업은 사용자가 그 서비스의 콘솔에서 직접 해야 하는 일이 있다(프로젝트·키 만들기, 동의 화면, 허용 주소, 테스트 사용자 등). Claude는 계정을 만들거나 콘솔에 값을 넣지 않는다.

1. **안내서를 먼저 쓴다.** 하위 세션을 시작하기 전에 부모가 `docs/외부-준비-<서비스>.md`(공개 저장소면 저장소 밖이나 비밀값 없는 내용만)를 쓴다.
   - 단계마다 **어느 화면에서 무엇을 누르고 어떤 값을 넣는지**(예: 승인된 JavaScript 원본 = `https://<사용자>.github.io`, 끝에 `/` 없음)
   - 이 프로젝트에 맞게 미리 정한 값: 앱 이름, 지원 이메일 칸에 무엇을 쓰는지, 범위(scope)는 가장 좁게, 리디렉션 주소
   - 비용이 드는지, 무료 한도, 결제 정보가 필요한지(필요하면 그 단계는 사용자 몫이라고 적는다)
   - **자주 나는 오류와 고치는 법**: 예 `origin_mismatch` → 원본 주소 등록, `access_denied 403` → 테스트 사용자에 계정 추가, 사용자 사이트 루트가 404 → 사용자 사이트 저장소 필요
   - 다 하면 Claude에게 알려 줄 값(공개 값만, 예: 클라이언트 ID)
2. **진행 중에 외부 서비스가 필요해지면** 부모가 이때 안내서를 쓰고, 그 일에 기대는 체크리스트 줄은 ⏸로 두고 가짜 연결까지만 진행한다. 같은 일을 하는 무료 대안이 있으면 추천대로 골라도 되고 바꾼 것은 체크리스트에 적는다. **실제 계정으로 로그인해 보는 확인**과 **동의 화면을 테스트에서 프로덕션으로 게시하는 일**은 사용자 몫이다(공개 결정).
3. **그동안 코드는 브랜치에서 진행한다.** 외부 값이 필요 없는 부분(화면, 저장 형식, 가짜 연결로 하는 테스트)을 먼저 만들고, 값이 오면 이어서 붙인다. 배포는 실제 연결 확인 뒤에.
4. 사용자가 콘솔 화면을 물으면 안내서의 그 단계를 가리키며 답하고, 새로 알게 된 것은 안내서에 더한다.

## 비밀값

| 종류 | 예 | 저장소에 넣나 |
|---|---|---|
| 공개해도 되는 값 | OAuth 클라이언트 ID, 공개 API 키(도메인 제한 걸린 것), 사이트 주소 | 넣어도 된다. 코드나 설정 파일에 |
| 비밀값 | 클라이언트 시크릿, 서비스 계정 키(JSON), 개인 토큰, 비밀번호 | **절대 넣지 않는다.** 공개 저장소는 물론 비공개 저장소도. 사용자가 채팅에 붙여 넣으려 하면 붙이지 말라고 안내한다 |
| 사용자 로그인 토큰 | 접근 토큰, 새로 고침 토큰 | 브라우저 저장소에만, 짧게. Base64는 암호화가 아니라고 알린다 |

- 서버 없는 웹앱은 비밀값을 둘 곳이 없다. 비밀값이 꼭 필요한 설계면 진행하기 전에 사용자에게 알린다(서버가 필요하다는 뜻이다).
- 커밋 전에 `git diff --cached`에서 키처럼 보이는 문자열(`secret`, `client_secret`, `private_key`, `-----BEGIN`, `GOCSPX-`, `ghp_`, `gho_`, `sk-` 등, `AIza`는 도메인 제한이 걸린 공개 키일 수 있어 경고만)을 찾는다.
- **사용자가 이미 비밀값을 채팅에 붙여 넣었으면**: 그 값을 다시 적거나 파일·커밋으로 옮기지 않는다. 콘솔에서 그 시크릿을 재설정(새로 만들고 옛것 지우기)하라고 안내한다. 안내서 단계에는 "JSON 내려받기 대신 클라이언트 ID만 복사"를 넣는다.
- 브리프의 고정 규칙에 "비밀값은 저장소에 넣지 않는다"를 넣는다.
