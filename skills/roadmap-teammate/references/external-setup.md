# 외부 준비와 비밀값

## 사용자가 바깥에서 해야 하는 준비

로그인, 클라우드 저장, 결제, 지도, 알림처럼 외부 서비스가 필요한 작업은 사용자가 그 서비스의 콘솔에서 직접 해야 하는 일이 있다(프로젝트·키 만들기, 동의 화면, 허용 주소, 테스트 사용자 등). Claude는 계정을 만들거나 콘솔에 값을 넣지 않는다.

1. **사용자가 콘솔에서 할 일이 있으면 단계·넣을 값·비용을 먼저 알려 준다.** 다 하면 Claude에게 알려 줄 값(공개 값만, 예: 클라이언트 ID)도 함께 적는다.
2. **외부 값이 필요 없는 부분을 먼저 브랜치에서 진행한다.** 화면, 저장 형식, 가짜 연결로 하는 테스트를 먼저 만들고, 값이 오면 이어서 붙인다. 그 값에 기대는 체크리스트 줄은 ⏸로 둔다. 배포는 실제 연결 확인 뒤에. **실제 계정으로 로그인해 보는 확인**과 **동의 화면을 테스트에서 프로덕션으로 게시하는 일**은 사용자 몫이다(공개 결정).
3. **서비스를 바꾸는 건 선택 UI로 묻는다.** 같은 일을 하는 무료 대안이 있어도 쓰는 서비스를 바꾸는 건 제품 선택이다(선택지: 무료 대안으로 바꾸기 / 원래 서비스 그대로, 비용 안내와 함께). 사용자가 자리를 비웠으면 바꾸지 않고 그 줄을 ⏸로 둔다.
4. **사용자가 손으로 하는 절차는 한 단계씩 같이 간다.** 서버 배포, 터미널 명령, 콘솔 설정처럼 사용자가 직접 해야 하는 일이 여러 단계면 한 번에 다 주지 않는다.
   - 한 번에 한 단계만 준다: 무엇을 하는지 한 줄, 그대로 붙여 넣을 명령이나 넣을 값, "결과(출력이나 화면 문구)를 붙여 주세요".
   - 붙여 준 결과를 보고 됐으면 다음 단계로, 아니면 그 결과에 맞춘 고침 한 단계를 준다. 결과에 비밀값이 보이면 아래 "비밀값"대로 한다.
   - 휴대폰에서도 따라 하기 쉽게, 명령은 한 줄씩 코드 블록에 넣는다.

## 비밀값

| 종류 | 예 | 저장소에 넣나 |
|---|---|---|
| 공개해도 되는 값 | OAuth 클라이언트 ID, 공개 API 키(도메인 제한 걸린 것), 사이트 주소 | 넣어도 된다. 코드나 설정 파일에 |
| 비밀값 | 클라이언트 시크릿, 서비스 계정 키(JSON), 개인 토큰, 비밀번호 | **절대 넣지 않는다.** 공개 저장소는 물론 비공개 저장소도. 사용자가 채팅에 붙여 넣으려 하면 붙이지 말라고 안내한다 |
| 사용자 로그인 토큰 | 접근 토큰, 새로 고침 토큰 | 브라우저 저장소에만, 짧게. Base64는 암호화가 아니라고 알린다 |

- 서버 없는 웹앱은 비밀값을 둘 곳이 없다. 비밀값이 꼭 필요한 설계면 진행하기 전에 사용자에게 알린다(서버가 필요하다는 뜻이다).
- 커밋 전에 `git diff --cached`에서 키처럼 보이는 문자열(`secret`, `client_secret`, `private_key`, `-----BEGIN`, `GOCSPX-`, `ghp_`, `gho_`, `sk-` 등, `AIza`는 도메인 제한이 걸린 공개 키일 수 있어 경고만)을 찾는다.
- **사용자가 이미 비밀값을 채팅에 붙여 넣었으면**: 그 값을 다시 적거나 파일·커밋으로 옮기지 않는다. 콘솔에서 그 시크릿을 재설정(새로 만들고 옛것 지우기)하라고 안내한다. 콘솔 단계를 알려 줄 때 "JSON 내려받기 대신 클라이언트 ID만 복사"를 넣는다.
- 브리프의 고정 규칙에 "비밀값은 저장소에 넣지 않는다"를 넣는다.
