# PR과 머지 (roadmap-teammate 13절)

하위 세션이 PR을 만들 때, 부모가 머지할 때 읽는다. 위험한 PR을 검토할 때, 검토 지적이 나왔을 때, 브리프에 돌릴 테스트를 적을 때, CI를 만들거나 CI가 돌지 않을 때는 아래 같은 이름의 절을 읽는다. 절 번호(0절, 5절 등)는 [../SKILL.md](../SKILL.md)의 절이다.


- **한 작업 = 브랜치 하나 = PR 하나.** 하위 세션은 자기 worktree에서 일하고 끝나면 기본 브랜치 대상 PR을 만든다. 코드 개선·테스트·검증·추가 피드백(부모의 `SendMessage`, PR 리뷰 댓글, CI 실패)은 모두 같은 PR에 커밋을 더해 처리한다. 필요하면 검토 세션이 같은 PR을 리뷰한다.
- **같은 파일을 건드리는 일은 동시에 돌리지 않는다.** 겹치지 않는 일은 각자 worktree에서 함께 돌린다. 프로젝트 규칙([projects.md](projects.md))에 동시 worktree 개수 제한이 있으면 따른다. 머지하면 "머지 뒤 정리"대로 `git worktree remove <경로>`·`git branch -D <브랜치>`로 지운다(원격 브랜치는 머지 때 `--delete-branch`). "그대로 둠"으로 남긴 폴더는 마무리 보고에 적는다.
  - 폴더마다 무거운 다시 가져오기·빌드가 필요한 프로젝트(게임 엔진 등)는 엔진을 띄워 테스트하는 코드 일을 기본 사본에서 하나씩 한다(`use_worktree: false`). 이 세션에는 브리프에 "기본 브랜치에서 새 브랜치를 만들어 일하고, PR을 만든 뒤 기본 브랜치로 돌아갈 것"을 적는다. 기본 사본은 한 세션이 쓰는 동안 다른 세션에 주지 않는다. 따로 worktree는 문서 일이나 엔진과 상관없는 코드 일에 쓴다.
- **PR 본문 = 최종 요약.** 하위 세션이 쓰고 커밋을 더할 때마다 갱신한다.
  ```
  ## 무엇을 바꿨나
  - <체크리스트 번호> <한 줄>
  ## 어떻게 확인했나
  - `<명령>` → 종료 코드 0, <결과 줄 그대로, 예: 12 passed>
  - 돌리지 않은 범위: <예: 전체 테스트는 마일스톤 끝에>
  ## 범위 밖에서 건드린 것
  - 없음
  ## 확인 못 한 것·남은 것
  - …
  ## 나중에
  - <사소한 검토 지적, 없으면 칸째 뺀다>
  ```
  - "어떻게 확인했나"는 부모가 시험을 다시 돌리지 않고 읽는 증거다(SKILL.md 5절 2번). "통과" 한 마디가 아니라 명령·종료 코드·결과 줄을 그대로 적는다. 흔들리는 시험을 되풀이했으면 "3번 중 3번 통과"처럼 횟수도 적는다.
- **머지는 부모가 한다.** 하위 세션은 PR까지만. 부모는 5절 확인 항목 4개(위험한 PR이면 검토 한 번도)를 본 뒤 0절 권한대로 머지한다(추천 답이면 사용자에게 선택 UI로 묻고 머지). 태그는 사용자가 요청할 때만(0절) 머지 뒤 기본 브랜치에 단다. 번호 꼴은 roadmap [rules.md "태그"](../../roadmap/references/rules.md)를 따르고, 주석 태그에 결과 핵심을 적는다.
- **커밋 메시지 꼴 (모든 커밋: 하위 세션의 커밋, squash 커밋, PR 없이 하는 커밋).** 프로젝트 CLAUDE.md에 커밋 형식이 따로 있으면 그것을 따른다.
  - 제목 = `<타입>: <결과 한 줄>`. 타입은 영어(Conventional Commits), 내용은 한국어로 "무엇이 됐나"를 쓴다. 50자 안팎, 끝에 마침표 없음.
  - 타입: `feat`(새 기능) · `fix`(버그 고침) · `docs`(문서·README) · `style`(화면 꾸밈·서식, 동작 같음) · `refactor`(동작 같은 코드 정리) · `test`(테스트) · `perf`(빠르게) · `build`(설치·빌드·의존성) · `ci`(CI 설정) · `chore`(그 밖의 잡일). 여러 개에 걸치면 가장 큰 결과의 타입 하나.
  - 본문 = 결과 핵심만 `- `로 1~6줄. 과정·시행착오는 적지 않는다. 한 줄로 충분한 작은 커밋은 본문을 생략해도 된다. 꼬리표는 0절 답대로 맨 끝에.
  - 한 커밋 = 목적 하나. 목적이 다르면 커밋을 나눈다.
- **머지는 Squash and merge로 한다.** PR 하나가 기본 브랜치에 커밋 하나로 남는다(`gh pr merge <번호> --squash --subject "<제목>" --body "<본문>" --delete-branch`). 제목·본문은 위 커밋 메시지 꼴, 제목 끝에 PR 번호. 중간 커밋은 나열하지 않고 PR 전체의 결과만 쓴다. PR 제목도 같은 `<타입>: <결과>`로 쓴다.
  ```
  docs: 커밋 메시지 꼴과 컨벤션을 정함 (#16)

  - 모든 커밋 제목을 <타입>: <결과 한 줄>로
  - 타입 10가지와 고르는 법
  - squash 커밋도 같은 꼴, 끝에 PR 번호

  Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>
  ```
- **머지를 물을 때 보고 꼴.** 사용자가 머지 전에 결과를 다 알게 쓴다. 칸 이름과 번호·상태 표시는 그대로 두고, 칸 안의 문장만 구어체로 쓴다. 설치·배포처럼 머지 뒤에 생기는 일도 먼저 적는다.
  ```
  **무엇**: <PR 링크> — <체크리스트 번호> <한 줄>
  **확인**: 요약 통과(4칸) · 테스트 통과(CI / 세션 출력 읽음 / 직접 돌림(위험)) · 범위 통과(파일 3개, 범위 밖 없음) · 충돌 없음 · 검토: 안 함(위험 아님) / 함(저장 코드) — 꼭 고칠 것 없음, 나중에 2개
  **확인 못 한 것·남은 것**: <PR 본문 "확인 못 한 것·남은 것" 칸 그대로, 사람이 직접 해 볼 것 포함>
  **머지하면**: 배포 여부 · 따로 할 설치·반영(예: `./install.sh`)
  1) 머지하고 설치·반영 (추천) 2) 머지만 3) 아직 안 함(PR 열어 두기)
  ```
  - 확인 4개는 항목마다 통과/걸림을 적는다. 테스트는 어떻게 확인했는지(CI / 세션 출력 읽음 / 직접 돌림(위험))를 적는다. 위험한 PR이면 검토 결과도 한 줄 적는다(아래 "위험한 PR 검토"). 걸린 게 있으면 묻지 않고 5절대로 고치게 한다.
  - "나중에" 칸이 있으면 "나중에 N개" 한 마디를 넣는다(머지를 막지 않는다, 아래 "검토 지적 나누기").
  - 선택지는 선택 UI로도 묻는다. 고른 대로 머지·설치를 하고, 하위 세션은 아래 "머지 뒤 정리"대로 정리한 뒤 결과를 한 줄로 보고한다. 정리 방법은 묻지 않는다.
  - 0절에서 머지까지 맡겼으면(아래 배포 예외 빼고) 묻지 않고 머지하고, 같은 꼴(선택지 빼고)로 머지 뒤 보고한다. 하위 세션 정리도 아래 "머지 뒤 정리"대로 한다.
- **머지 뒤 정리.** 머지한 PR의 하위 세션은 묻지 않고 기본으로 보관한다. 사용자가 "내 방식"([projects.md](projects.md))에 다르게 적어 뒀으면 그대로 한다(SKILL.md 0절 기본값).
  1. **보관**(기본): 세션을 보관하고(`archive_session`, 되돌릴 수 있음) worktree 폴더와 로컬 브랜치를 지운다.
  2. **삭제**: 되돌릴 수 없어서 사용자가 "삭제"라고 정해 뒀을 때만 한다. 세션과 대화를 지우고(`delete_session`, 앱이 한 번 더 확인한다) 그 worktree 폴더와 로컬 브랜치도 지운다.
  3. **그대로 둠**: 사용자가 정해 뒀을 때만. 세션과 worktree 폴더를 남긴다. 원격 브랜치만 머지 때 지운다.
  - 세션이 worktree 폴더를 열어 두고 있으면 "사용 중"이라 폴더가 지워지지 않는다. 그래서 세션을 먼저 지우거나 보관한 뒤 폴더를 지운다. 부모의 작업 폴더가 그 worktree 안이어도 안 지워지므로, 지우기 전에 부모는 `git -C <기본 사본>`처럼 기본 사본을 가리켜 명령한다(그 worktree 안에서 지우지 않는다).
  - 머지되지 않은 PR의 세션이나 PR이 없는 세션은 정리하지 않고, 정리할지 보고에 적는다.
- **PR이 여럿이면 하나씩 머지한다.** 먼저 머지된 것과 충돌하면 그 PR의 세션이 기본 브랜치를 받아 고친 뒤 머지한다.
- 예외:
  - GitHub 원격이 없거나 git이 아닌 프로젝트: PR 없이 지금처럼 커밋만 한다. 커밋 메시지는 위 커밋 메시지 꼴로 쓴다(5절은 `git log`·diff 요약·테스트 결과로 본다).
  - main push가 곧 배포인 프로젝트: 머지가 배포다. 0절에서 머지까지 맡겼어도 머지 때 따로 선택 UI로 확인한다. 자리 비움 중이면(10절) 머지하지 않고 "돌아오시면 정할 것"에 둔다.
  - 한 번에 하나만 도는 도구(1절): worktree를 나눠도 세션은 순서대로 돌린다.
  - 서로 기대는 작업: 앞 PR이 머지된 뒤 다음 세션을 시작한다.

## 위험한 PR 검토

SKILL.md 5절 확인 항목 4개만으로는 "틀렸지만 테스트는 통과하는 구현"을 못 거른다. 그래서 위험한 PR만 한 번 더 본다(4개 + 위험할 때만 검토 한 번). 위험하지 않은 PR은 4개만 본다.

- 위험한 PR: 저장·네트워크처럼 여러 기능이 같이 쓰는 코드 · 형식·스키마·버전 번호 변경 · 인증·결제·비밀값에 닿는 코드 · CI가 없는데 테스트도 새로 쓴 PR.
- 방법: 부모가 `Agent` 서브에이전트(0절 테스트·검토 모델)에 PR diff(`gh pr diff <번호>`)와 브리프의 "할 일·끝난 모습"만 준다. 하위 세션의 보고와 PR 본문은 주지 않는다(편향 방지).
- 보게 할 것: 브리프대로 됐나 · 테스트가 정말 그 동작을 확인하나 · 틀리게 통과할 길이 있나.
- 위험한 PR은 시험도 부모가 그 PR 브랜치에서 한 번 직접 돌린다(SKILL.md 5절 2번).
- 머지 보고 "확인" 줄에 검토했는지와 결과 한 줄을 적는다(위 "보고 꼴").

## 검토 지적 나누기

PR 검토(위험한 PR 검토 서브에이전트, 리뷰 댓글, 검토 세션)에서 나온 지적은 머지 전에 둘로 나눈다(사소한 것은 적어 두고 넘어간다). 검토 서브에이전트든 다른 PR 검토든 같다. 사소한 것까지 고치고 다시 검토하면 PR 하나가 끝나지 않는다.

| 나누기 | 예 | 하는 일 |
|---|---|---|
| 꼭 고칠 것 | 동작이 틀림 · 데이터가 날아감 · 보안 · 시험 빠짐 | 4개가 걸렸을 때처럼 그 세션에 `SendMessage`로 같은 PR에 커밋을 더해 고치게 한다(SKILL.md 5절 끝). 고친 곳만 다시 본다. |
| 사소한 것 | 이름 · 주석 · 꾸밈 · 작은 중복 | 그 PR에서 고치지 않는다. PR 본문 "나중에" 칸에 한 줄씩 적고 머지한다. 검토를 다시 돌리지 않는다. |

- 헷갈리면 "이대로 머지하면 사용자나 데이터가 다치나"로 가른다. 다치면 꼭 고칠 것이다.
- 머지 보고에 "나중에 N개"를 적는다.
- 쌓인 "나중에"는 부모가 모아 PR 하나로 한 번에 고친다([splitting.md](splitting.md) "작은 일은 부모가 직접"). 그 PR 본문 "무엇을 바꿨나"에 원래 PR 번호를 적는다. 마일스톤 끝(SKILL.md 11절 마무리)에 남은 "나중에"가 있으면 보고 "다음" 선택지에 넣는다.

## PR에서 돌릴 테스트

관련 테스트 먼저, 전체는 마일스톤 끝에 돌린다. 프로젝트 CLAUDE.md에 테스트 규칙이 따로 있으면 그쪽을 따른다. 없으면 브리프 "끝난 모습"에 이렇게 적는다.

- PR마다 구현과 그 기능에 닿는 테스트만 돌린다: 단위 테스트 전체, 그 기능의 테스트, 배포·빌드 검사.
- 형식·스키마·버전 번호를 바꾼 PR은 그 번호를 grep해서, 그 번호를 확인하는 테스트도 함께 돌린다.
- 저장·네트워크처럼 여러 기능이 같이 쓰는 코드를 바꾸면 PR에서도 전체 테스트를 돌린다.
- 전체 테스트는 마일스톤이 끝날 때 기본 브랜치에서 한 번 돌린다([wrap-up.md](wrap-up.md) "마무리" 3).
- PR 본문 "어떻게 확인했나"에 돌린 명령·종료 코드·결과 줄과 돌리지 않은 범위를 적는다(부모가 이것으로 확인한다, SKILL.md 5절 2번).
- 흔들리는 시험(돌릴 때마다 결과가 다른 것)은 하위 세션이 3번(기본, "내 방식"에서 바꿈) 되풀이해 다 통과해야 통과로 치고, 횟수와 결과를 본문에 적는다.

## CI 시간

비공개 저장소는 Actions 시간이 한도·돈이다. 하위 세션을 여럿 돌리면 PR이 늘어 금방 찬다.

- CI를 만들거나 고칠 때는 테스트에 닿는 파일이 바뀔 때만 돌게 하고(`paths`), 같은 PR의 앞 실행은 끊는다(`concurrency`). 문서만 바뀐 PR에는 돌지 않게 한다. 시험에 닿는 경로를 빠뜨리지 않는다.
- CI가 몇 초 만에 실패하면 시험 실패로 보지 말고 잡이 시작됐는지부터 본다.
- 한도나 결제로 잡이 시작되지 않으면 사용자에게 알리고 로컬 시험으로 이어 갈지 선택 UI로 묻는다. 결제는 사용자 몫이다. 이어 가면 PR마다는 SKILL.md 5절 2번(CI가 안 돌았을 때)대로 본다. PR 여럿을 합친 판은 어느 세션도 돌리지 않았으니 부모가 CI와 같은 명령을 한 번 직접 돌려 종료 코드와 결과 줄을 보고 머지한다.
- 머지할 때 저장소 조건을 건너뛰는 옵션(`--admin`)은 사용자가 말하지 않으면 쓰지 않는다.
