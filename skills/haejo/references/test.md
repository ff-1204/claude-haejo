# 테스트와 검토

테스트 단계([../SKILL.md](../SKILL.md) 6절)에서 돌릴 범위를 정할 때, 위험한 변경을 검토할 때, 검토 지적이 나왔을 때 읽는다.

## 돌릴 테스트

관련 테스트 먼저, 전체는 마일스톤 끝에 돌린다. 프로젝트 CLAUDE.md에 테스트 규칙이 따로 있으면 그쪽을 따른다.

- 일마다 구현과 그 기능에 닿는 테스트만 돌린다: 단위 테스트 전체, 그 기능의 테스트, 배포·빌드 검사.
- 형식·스키마·버전 번호를 바꿨으면 그 번호를 grep해서, 그 번호를 확인하는 테스트도 함께 돌린다.
- 저장·네트워크처럼 여러 기능이 같이 쓰는 코드를 바꿨으면 전체 테스트를 돌린다.
- 전체 테스트는 마일스톤이 끝날 때 한 번 돌린다([wrap-up.md](wrap-up.md) "마무리").
- 얻거나 열리는 규칙을 만들었으면 점검표에서 걸려 고친 줄을 테스트로 남긴다([systems.md](systems.md) "말이 되나 점검").
- 돌린 명령·종료 코드·결과 줄과 돌리지 않은 범위를 보고의 "어떻게 확인했나"에 그대로 적는다. "통과" 한 마디로 적지 않는다.
- **시험이 뒤에서 도는 동안 멈추지 않는다.** 오래 걸리는 시험을 뒤에서 돌려 놓았으면 중간 보고로 일을 끝내지 않는다. 기다리는 동안 할 수 있는 일(시안 대조, 문서, 커밋 메시지 준비)을 하고, 할 일이 없으면 끝났다는 알림을 기다린다(되풀이해 들여다보지 않는다). 시험이 통과하면 받은 git 범위(커밋·PR·머지)까지 이어서 한 뒤 마무리 보고를 한다. 실패하면 개발로 돌아가 고친다. 사용자가 "이어서 해줘"라고 다시 말해야 하게 두지 않는다.
  - 멈추는 곳은 그대로다: 받지 않은 git 범위, 배포가 되는 머지 직전의 확인, CI가 대기로 끝나지 않을 때의 물음([git.md](git.md) "머지", "CI 시간").
  - 자리를 비웠으면 그 물음들은 묻지 않고 "돌아오시면 정할 것"에 두고 나머지를 이어 한다([wrap-up.md](wrap-up.md) "자리 비움").
- 흔들리는 시험(돌릴 때마다 결과가 다른 것)은 3번(기본, "내 방식"에서 바꿈) 되풀이해 다 통과해야 통과로 치고, 횟수와 결과를 적는다.

## 위험한 변경 검토

시험과 시안 대조만으로는 "틀렸지만 테스트는 통과하는 구현"을 못 거른다. 만든 쪽과 확인하는 쪽이 같은 세션이면 더 그렇다. 그래서 위험한 변경만 다른 눈으로 한 번 더 본다.

- 위험한 변경: 저장·네트워크처럼 여러 기능이 같이 쓰는 코드 · 형식·스키마·버전 번호 변경 · 인증·결제·비밀값에 닿는 코드 · 파일이나 데이터를 지우는 코드 · 자동 시험(CI) 없이 테스트도 새로 쓴 변경 · 규칙의 뜻을 바꾸는 문서 변경 · 써 보는 중에 제품 안의 규칙을 새로 넣거나 조건을 바꾼 변경(묶어서, 아래).
- 써 보는 중에 들어온 규칙 변경([mockup.md](mockup.md) "써 보는 중에 들어온 규칙 변경")은 하나마다 검토하지 않는다. 그 턴 보고의 "확인 못 한 것"에 "규칙 검토 전 N건"을 적고, 한 대화에서 세 번째가 쌓이면 묶어서 한 번 검토한다. 세 번이 안 됐어도 커밋·PR·머지 전과 [wrap-up.md](wrap-up.md) "마무리" 때는 한 번 한다. 보게 할 것에 "말이 되나"와 "규칙끼리 부딪히나"를 더한다([systems.md](systems.md) "말이 되나 점검").
- 방법: `Agent` 하위 에이전트(SKILL.md 2절 기본값의 모델)에 바뀐 내용(`git diff`, PR이면 `gh pr diff <번호>`)과 기준(확정 시안이나 "끝났다고 보는 것")만 준다. 이 세션의 요약, 보고, PR 본문은 주지 않는다(편향 방지). 읽기만 하게 한다.
- 보게 할 것: 기준대로 됐나 · 테스트가 정말 그 동작을 확인하나 · 틀리게 통과할 길이 있나 · 옮기거나 줄이면서 빠진 것이 있나.
- 보고의 "어떻게 확인했나"에 검토했는지와 결과 한 줄을 적는다(예: "검토: 함(지우는 코드) — 꼭 고칠 것 1개 고침, 나중에 2개").

## 검토 지적 나누기

검토에서 나온 지적은 둘로 나눈다. 사소한 것까지 고치고 다시 검토하면 일이 끝나지 않는다.

| 나누기 | 예 | 하는 일 |
|---|---|---|
| 꼭 고칠 것 | 동작이 틀림 · 데이터가 날아감 · 보안 · 시험 빠짐 · 규칙의 뜻이 바뀜 | 개발로 돌아가 고친다. 고친 곳만 다시 본다. |
| 사소한 것 | 이름 · 주석 · 꾸밈 · 작은 중복 | 고치지 않는다. 보고(PR이면 본문)의 "나중에" 칸에 한 줄씩 적는다. 검토를 다시 돌리지 않는다. |

- 헷갈리면 "이대로 두면 사용자나 데이터가 다치나"로 가른다. 다치면 꼭 고칠 것이다.
- 쌓인 "나중에"는 모아서 한 번에 고친다. 마일스톤 끝에 남아 있으면 보고의 "다음" 선택지에 넣는다.
