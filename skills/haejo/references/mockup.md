# 시안 먼저

만들기 전에 시안을 보이고 확정받을 때, 끝난 뒤 시안과 대조할 때 읽는다([../SKILL.md](../SKILL.md) 4절, SKILL.md 6절).

흐름: 요청 → 시안 → 사용자 검토·수정 → 확정 → 만들기 → 시안대로 됐는지 확인.

## 언제 만드나

| 만든다 | 만들지 않는다 |
|---|---|
| 사용자가 보거나 정하는 결과가 있는 일: 새 기능, 화면·문구·흐름, 제품 안의 규칙·시스템, 제품에 담기는 내용물, 문서 구조나 규칙을 바꾸는 일, 여러 단계에 걸친 일 | 버그 고침처럼 바른 결과가 하나뿐인 일 |
| | 한두 파일만 고치는 작은 일(문구 하나, 표시 조건, 순서) |
| | 사용자가 "시안 없이"라고 한 일 |
| | 로드맵 세부 항목: 그 줄의 "끝났다고 보는 것"이 시안 구실을 한다. 화면·문구가 걸린 줄만 시안을 거친다(아래 "화면 틀 시안") |

## 화면 틀 시안

화면 틀 시안 규칙의 원본은 여기다. 사용자가 보는 화면이 있는 제품인데 만든 화면도 확정된 화면 틀도 아직 없으면, 화면이 걸린 첫 줄을 만들기 전에 주요 화면 두세 개의 배치와 분위기를 시안으로 한 번 확정받는다. 이 문서들에서 "화면 틀 시안이 필요하다"는 이 경우다.

- 해당 없는 것: 화면이 없는 제품(명령줄 도구, 라이브러리), 이미 화면이 있는 프로젝트. 한 주제 기획이라도 그 프로젝트의 첫 화면을 만드는 일이면 해당한다.
- 기획이 끝났을 때 다음 할 일 1번은 이 시안이고, 개발은 2번이다([plan.md](plan.md) "묻는 지점").
- 규칙 시안이 확정돼 있으면(`concept.md` 3절) 그 규칙이 드러나는 장면으로 그린다. 한 장면만 여러 모양으로 그리지 않고, 확정한 시스템마다 그것이 보이는 화면을 넣는다.
- 틀에 넣을 화면과 그 뒤에 그릴 화면은 Claude가 골라 정하지 않고 시안 한눈표(`concept.md` 3절, [systems.md](systems.md))에서 가져온다. 화면 시안 칸이 빈 줄이 남은 화면이다. 기본 요소의 화면(목록, 설정, 내 정보처럼 어디에나 있는 화면)도 줄이 있으면 들어간다. 시안을 확정할 때마다 그 줄의 화면 칸을 고치고, 남은 줄 수를 알린다.
- 틀(주요 화면 두세 개)을 확정하면 `roadmap.md`에 `> 화면 틀:` 줄을 적는다. 그 뒤 남은 화면 칸은 시안 범위에 따른다.
  - "먼저 만들 것만": 남은 빈칸을 `미룸`으로 적는다. 그 줄을 만드는 마일스톤을 시작할 때 시안을 거친다.
  - "전부 먼저": 빈칸이 없어질 때까지 묶음으로 나눠 이어 그린다. 빈칸이 남은 동안에는 다음 할 일 1번을 남은 시안으로 두고, 개발이나 기획 다시 짜기를 먼저 권하지 않는다.
- 한눈표가 없으면(조사·규칙 시안 단계를 돌지 않은 기획) 주요 화면을 Claude가 고르되, 무엇을 골랐고 무엇을 남겼는지 목록으로 함께 보인다.
- 사용자가 개발을 고르거나 "M1 진행해줘"라고 해도 틀이 없으면 이 시안부터 하고, 첫 줄에 그렇게 알린다. 사용자가 "시안 없이"라고 하면 건너뛴다.
- 확정되면 `roadmap.md` 머리 인용 블록에 `> 화면 틀: 확정 YYYY-MM-DD (<시안 링크나 파일>)` 한 줄을 적는다. 건너뛰었으면 `> 화면 틀: 시안 없이 진행`이라고 적는다. 이 줄이 있으면 다시 하지 않는다(새 세션과 하위 세션은 이 줄로 판단한다).
- 확정 뒤 줄들은 틀을 기준으로 삼는다. 화면·문구가 걸린 줄 가운데 틀에 없는 새 화면이나 문구가 나오는 줄만 다시 시안을 거친다.
- 화면이 걸리지 않은 줄(저장 형식, 계산 규칙)은 틀을 기다리지 않는다. 자리를 비웠는데 틀이 확정되지 않았으면 화면이 걸린 줄은 "돌아오시면 정할 것"에 두고 나머지를 한다.

## 그리기 전에

- **참고 제품 조사**: 사용자가 참고할 제품을 말했거나 "조사해서"라고 했으면, 시안을 그리기 전에 그 제품이 이 기능을 어떻게 하는지 조사한다. 말한 제품 한두 개의 그 기능만 보고(제품을 말하지 않고 "조사해서"라고만 했으면 그 기능으로 잘 알려진 제품 두세 개를 골라 무엇을 봤는지 적는다), `Agent` 하위 에이전트에 맡겨 결과만 가져온다. 웹 검색을 쓸 수 없으면 아는 것으로 쓰고 "조사 못 함"이라고 적는다. 시안에 "가져올 것 / 가져오지 않을 것"을 까닭과 함께 넣는다. 방식만 가져오고 이름·상표·글·그림은 쓰지 않는다([decisions.md](decisions.md) "라이선스·약관"). 말하지 않았으면 하지 않는다. 기획의 조사 단계([research.md](research.md))와는 따로다.
- **지금 있는 것과 겹침 확인**: 이미 돌아가는 프로젝트면 시안을 그리기 전에 지금 있는 기능·규칙·화면 가운데 이 일과 겹치거나 부딪히는 것을 코드와 문서에서 찾는다. 있으면 시안에 "지금 있는 것 ↔ 이렇게 정리"를 항목으로 넣어 함께 확정받는다(합치기, 바꾸기, 둘 다 두기 가운데 무엇인지). 아직 만든 기능이 없는 새 제품이면 하지 않는다.
  - 만들다가 겹침을 발견하면 그 항목을 멈추고 시안 검토로 돌아가 확인받는다. 자리를 비웠으면 그 항목만 "돌아오시면 정할 것"에 두고 나머지를 계속한다(아래 "확정된 시안이 기준").
  - 시안을 건너뛰는 일(버그 고침, 작은 고침, 로드맵 세부 항목)은 이 확인을 따로 하지 않는다. 다만 하다가 지금 있는 기능·규칙을 바꾸거나 없애야 하는 겹침이 보이면 작은 고침이 아니므로 시안 검토로 간다.

## 시안은 그림이다

시안은 표나 글이 아니라 **시각자료**다. 먼저 그림을 보이고, 글은 그림에 담지 못한 것만 짧게 붙인다. 긴 표를 읽고 번호로 고칠 곳을 짚게 하지 않는다.

| 무엇을 바꾸나 | 어떤 그림 |
|---|---|
| 화면·UI·사이트 | **Claude 아티팩트 페이지.** 실제 파일의 임시 사본을 고쳐 아티팩트로 게시하고 링크로 보인다(저장소 파일은 확정 전에 고치지 않는다). 고칠 때마다 같은 주소에 다시 올린다. 아티팩트를 쓸 수 없는 곳에서만 HTML 파일을 보내거나 실제 화면(스크린샷)을 바탕으로 한 "지금 ↔ 시안"을 보이고, 그 사실을 한 줄 적는다. 상자 그림으로 대신하지 않는다. 그리기 전에 쓸 수 있는 디자인 스킬을 먼저 부르고(SKILL.md 4절), [projects.md](projects.md) "공통"의 디자인 줄과 "내 방식"의 디자인 값을 따른다 |
| 흐름·순서 | 흐름도. 바뀌는 칸과 빠지는 칸을 색으로 가른다 |
| 제품 안의 규칙·시스템 | 시안 한눈표(전체 줄과 시안 상태를 적은 진행표)를 앞에 붙이고, 이어서 시스템마다 한 장: 조건 → 결과 흐름, 숫자 표, 처음부터 끝까지 따라가 본 예시 하나. 규칙 번호는 `R1`부터([systems.md](systems.md)) |
| 제품에 담기는 내용물(줄거리, 안내 글, 목록·분류) | 뼈대 한 장: 큰 덩이와 순서, 덩이마다 한두 줄. 실제 문장이나 항목 예시를 몇 개 넣는다 |
| 구조·규칙·문서 | "지금 ↔ 시안"을 나란히 놓은 그림. 무엇이 빠지고 무엇이 생기는지 한눈에 보이게 |
| 물어볼 화면·문구 | 실제로 보일 모습 그대로 그린 화면 |

- 화면이 아닌 것(흐름·구조·규칙)은 그림을 그릴 도구(그림 위젯, 아티팩트, 이미지)로 그린다. 없을 때만 글로 그린 그림(상자와 화살표)으로 대신하고, 그 사실을 한 줄 적는다.
- **올린 시안은 열어서 본 뒤에 보인다.** 화면 시안을 올리거나 다시 올렸으면 쓸 수 있는 도구(브라우저, 스크린샷)로 직접 열어 글자가 넘치거나 겹친 곳, 깨진 그림, 빈 화면이 없는지 본다. 걸리면 고쳐서 다시 올린 뒤 보인다. HTML 파일로 보내는 시안도 같다. 열 도구가 없거나 열기에 실패했을 때만 "눈으로 확인하지 못했다"고 까닭과 함께 적는다.
- 사용자가 화면 캡처로 깨진 곳이나 고칠 곳을 짚으면 그 자리를 고쳐 같은 아티팩트에 다시 올린다.
- 휴대폰에서 한 화면에 읽히게 그린다. 한 장에 다 안 들어가면 전체 한 장을 먼저 보이고 부분 그림을 잇는다.
- 그림 속 항목에는 번호를 붙여(`A1`, `A2` …) 사용자가 말로 짚을 수 있게 한다. 번호는 바꾸지 않는다(빠진 항목은 "(뺌)", 새 항목은 다음 번호).
- Claude가 추천으로 정한 것은 그림 아래에 "추천대로 정한 것"으로 따로 적는다.
- 사용자 취향인 결정(SKILL.md 5절: 화면 문구, 보상·답례, 처음 흐름, 이름 붙이기)은 시안에 넣고, 문구면 실제 문장을 쓴다. 시안 확정이 곧 그 답이다.

## 검토·수정과 확정

- 시안을 보인 뒤 사용자가 고치자고 하면 고친 그림을 다시 보이고, "이대로"라고 할 때까지 되풀이한다.
- 사용자가 무엇을 고칠지 말하지 않았으면 선택지를 늘어놓지 말고 "어디를 고칠지 말로 적어 주세요"라고 짧게 묻는다.
- 사용자가 까닭을 말하지 않고 무언가를 빼라고 하면, 범위를 짐작해 묻기 전에 까닭을 한 번 묻는다. 까닭이 핵심 경험의 뜻이면 `concept.md` 맨 위 지킬 것 표의 "해치는 것"에 더하고, 같은 까닭에 걸리는 다른 화면·기능·체크리스트 항목을 찾아 함께 보인다. 뺀 것을 되살리자고 설득하지 않는다. 뺀 것은 시안 한눈표의 그 칸을 `뺌 (<까닭>)`으로 고치고, 체크리스트 항목은 지우지 않고 ⏸로 표시한다.
- 고칠 때마다 바뀐 곳만 한두 줄로 알린다. 그림 전체를 글로 다시 설명하지 않는다.
- 확정 전에는 구현을 시작하지 않는다.

## 확정된 시안이 기준

- 확정 시안의 항목을 번호째 기준으로 적어 둔다. 하위 세션에 맡기면 브리프에 그대로 옮긴다([sessions.md](sessions.md) "브리프 쓰기").
- 시안에 없는 것을 더하지 않는다. 시안대로 못 하는 항목은 다르게 만들지 말고 이유와 함께 알린다.
- 진행 중 시안이 바뀌어야 하면 사용자에게 다시 확인받는다. 자리 비움 중이면 그 항목을 "돌아오시면 정할 것"에 두고 나머지를 계속한다.

## 시안 대조

- 끝나면 시안 항목마다 "됐음 / 안 됨 / 다르게 됨(이유)"을 표로 보인다. 화면이면 실제 화면을 함께 본다.
- 사용자에게 가는 마무리 보고는 이 표가 중심이다.
- 시험과 위험한 변경 검토(SKILL.md 6절)는 그대로 한다. 시안 대조가 대신하지 않는다.

```
| 항목 | 결과 |
|---|---|
| A1 저장 버튼 | 됐음 |
| A2 "저장했어요" 표시 | 됐음 |
| A3 다시 시도 버튼 | 다르게 됨: 버튼을 아래쪽에 (진행 중 사용자 확인 받음) |
```

## 자리 비움

- 떠나기 전에 시안을 확정받는다([wrap-up.md](wrap-up.md) "자리 비움").
- 확정받지 못한 일은 시작하지 않고 "돌아오시면 정할 것"에 둔다.
