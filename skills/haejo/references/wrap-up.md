# 마무리와 자리 비움

사용자가 자리를 비운다고 했을 때, 일이 다 끝나 마무리할 때 읽는다([../SKILL.md](../SKILL.md) 8절).

## 자리 비움

사용자가 "병원 다녀올게", "자러 갈게", "다되면 마무리해줘", "다른 PC에서 이어 할게"처럼 자리를 비운다고 하면 이 방식으로 바꾼다.

- **떠나기 전에 한 번만, 한 화면에 묶어 묻는다.** 사용자가 자리를 비운다고 말한 그 차례(아직 자리에 있을 때) 아래를 한 번의 선택 UI로 묻는다. 이미 이 세션에서 받은 답은 빼고 묻는다.
  1. git 범위(SKILL.md 2절의 선택지 그대로. 아직 안 받았을 때만)
  2. 남은 일 중 사용자가 정해야 할 것(취향·미루기·외부 서비스). 시안이 필요한 일은 이때 시안을 보이고 확정받는다([mockup.md](mockup.md) "자리 비움"). 확정받지 못한 일은 시작하지 않는다.
  3. 확인 창이 뜰 만한 명령(허락 목록에 없는 명령, 지우기, 새 도구 설치)이 남은 일에 있으면 미리 허락받을지
  4. 깨어 있기(keep awake)·컴퓨터 사용 허락이 필요한지
  5. "다른 PC에서 이어 할게"라고 했으면 배포가 아닌 브랜치(예: `wip/이어하기`)에 커밋·push할지(아래 "요청할 때만 하는 것")
  - 물은 뒤에는 "더 물을 것 없어요. <예상 시간> 뒤 끝날 것 같아요"처럼 더 물을 게 없다는 것과 예상 시간을 분명히 말한다.
- **그 뒤로는 묻지 않는다.** 선택 UI(`AskUserQuestion`)를 부르지 않는다. 답을 기다리는 동안 일이 멈추기 때문이다.
- **git**: 떠나기 전에 받은 범위만큼만 한다. 받지 않았으면 파일만 고치고, 커밋·PR·머지는 "돌아오시면 정할 것"에 둔다. "머지까지"를 받았어도 main push가 곧 배포인 저장소는 머지하지 않고 남긴다.
- 결정이 필요한 것은 나눠서 한다.
  - 되돌릴 수 있고 비슷한 제품·프로젝트 규칙으로 판단할 수 있는 것: 추천대로 정하고 "추천대로 정한 것"에 적는다.
  - 그중 **사용자 취향인 것**(제품을 쓰는 사람이 보는 문구·보상·처음 흐름, 핵심 경험): 추천대로 하되 보고 맨 위 "확인해 주세요"에 바꾼 문장·내용을 그대로 보인다.
  - 외부 서비스를 바꾸는 것: 하지 않고 그 줄을 ⏸로 둔다.
  - 결제, 계정, 공개 전환, 지우기처럼 되돌리기 어려운 것: 하지 않고 "돌아오시면 정할 것"에 모은다. 그 일에 기대는 작업만 멈추고 나머지는 계속한다.
- PC가 잠들면 세션도 멈춘다. 앱의 깨어 있기(keep awake)를 켤 수 있으면 켜고, 못 켜면 보고에 적는다.
- 맡은 일이 다 끝나면 아래 "마무리"를 하고 멈춘다. 새 일을 스스로 시작하지 않는다(SKILL.md 2절 '개발 범위'에서 더 맡긴 만큼은 이어 한다).

## 마무리

사용자가 "다되면 문서 정리하고 마무리해줘"라고 했거나, 자리 비움 중 맡은 일이 다 끝났거나, 마일스톤이 끝났을 때 한다. 아래만 순서대로 하고, 그 밖의 것은 "요청할 때만 하는 것"이다.

1. **남은 일 확인**: 맡은 줄이 다 끝났는지, 하위 세션을 썼으면 모두 끝났는지 본다. 덜 끝난 마일스톤(막힌 항목이 남음)은 끝 표시를 하지 않고, 끝난 줄만 체크리스트 ✅와 시나리오 갱신을 한다.
2. **전체 테스트**(마일스톤 끝): 프로젝트의 전체 테스트를 한 번 돌린다. 일마다는 관련 테스트만 돌렸으니([test.md](test.md) "돌릴 테스트") 여기가 전체 테스트 자리다. 깨진 것은 고친다. 함께 돌릴 때만 흔들리는 테스트는 "정해진 시간 기다리기"를 "조건 기다리기"로 고친다.
3. **시안 대조**: 시안이 있던 일은 항목마다 "됐음 / 안 됨 / 다르게 됨(이유)"을 표로 만든다([mockup.md](mockup.md) "시안 대조"). 보고의 중심이다.
4. **문서 정리**: 이번에 바뀐 것만 있는 문서에 맞춘다. README(사용법·기능), 개발 문서(CLAUDE.md 등), 체크리스트(✅·날짜·🆕), 기획 문서([plan.md](plan.md)의 갱신 플로우), QA 기록.
5. **이어 하기 메모**: 저장소 안 개발 문서(없으면 `docs/이어하기.md`)에 "지금 상태 · 진행 중이던 것 · 다음 할 일 · 사용자 몫"을 짧게 고친다. 공개 저장소면 [rules.md](rules.md) "공개 저장소"대로 내부 경로·비공개 저장소 이름을 뺀다.
6. **git**: 받은 범위만큼만 한다([git.md](git.md)). 받은 것이 없으면 하지 않고 보고에 "커밋·PR·머지는 말씀하시면 해요" 한 줄을 붙인다.

## 요청할 때만 하는 것

사용자가 말하면 한다. 말하지 않으면 하지 않고, 필요해 보이면 보고 "다음" 선택지에 한 줄로 넣는다.

- **다른 PC 준비**: "다른 PC에서 이어 할게"라고 하면 새 PC에서 저장소를 받아 문서대로 하면 이어 할 수 있는지 본다(설치 단계, 이 PC에만 있는 파일과 옮기는 법). 다른 PC는 원격에서만 받을 수 있으니, 배포가 아닌 브랜치(예: `wip/이어하기`)에 이어 하기 메모와 진행 중인 일을 push해야 한다. 이 push도 git 범위라 떠나기 전에 묻는다. push를 못 하면 보고 첫 줄에 "이 PC에만 있음"과 이유를 적는다.
- **정리 후보 보이기**: 머지된 작업 폴더·로컬 브랜치, 끝난 하위 세션, 안 쓰는 임시 폴더·파일, 큰 폴더(빌드 결과·캐시, 용량과 함께)를 "왜 지워도 되는지 · 되돌릴 수 있는지"와 함께 보이고, 고른 것만 지운다. 커밋되지 않은 변경이 있는 폴더는 후보에 넣지 않고 따로 알린다.
- **새 세션으로 넘기기**: 이어 하기 메모를 고친 뒤 새 세션을 제안한다. 넘길 것은 메모 경로, 처음 질문의 답, 열린 PR 목록뿐이다. 대화의 앞부분이 요약되기 시작했으면 말하지 않아도 한 번 제안한다.
- **메모리 정리**: 다음 세션이 알아야 할 결정·규칙·주의점을 메모리에 남기거나 고친다.

## 돌아오셨을 때 보고

휴대폰에서 한 화면에 읽히게 쓴다.

```
**한 것**: M2 7개 끝 (바뀐 파일 23개, PR #41)
**확인**: 전체 테스트 통과 · 휴대폰 화면 확인
**시안 대조**: A1 됐음 · A2 됐음 · A3 다르게 됨(버튼을 아래쪽에)
**확인해 주세요**: 1) 첫걸음 문구 "…" → "…" (추천대로 바꿈) 2) …
**추천대로 정한 것**: 1) … 2) …
**돌아오시면 정할 것**: 1) 커밋·머지 (받은 범위 밖) 2) … (왜 사용자 몫인지)
**사용자 몫**: T1 두 속도로 며칠 놀아 보기
**다음**: 1. M3 시작 (추천) 2. …
```
