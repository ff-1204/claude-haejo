# 하위 세션을 쓸 때

처음 질문에서 "하위 세션에 맡기기"를 받았거나 사용자가 "세션 만들어서 해줘"라고 했을 때만 읽는다. 기본은 이 세션(메인)이 직접 하는 것이다([../SKILL.md](../SKILL.md) 5절).

## 언제 쓰나

- 한 대화에 다 들어가지 않을 큰 일(마일스톤 하나, 파일 수십 개)이고 사용자가 맡기라고 했을 때.
- 사용자가 따로·동시에·백그라운드로 하라고 했을 때.
- 그 밖에는 만들지 않는다. 결과를 이번 턴에 바로 쓰는 조사·검토는 `Agent` 하위 에이전트로 한다.
- 같은 파일을 건드리는 일은 동시에 돌리지 않는다. 한 번에 하나만 도는 도구(게임 엔진 배치 실행, 같은 포트의 개발 서버, 같은 DB)를 쓰는 일도 차례로 돌린다([projects.md](projects.md)).
- 마일스톤 일은 마일스톤마다 세션 하나다. 같은 마일스톤의 다음 줄은 그 세션에 `SendMessage`로 이어 맡기고, 번호가 바뀌면 새 세션을 만든다.

## 브리프 쓰기

하위 세션은 브리프만 보고 일한다. 매번 아래 순서로 쓴다(사용자의 언어, 결과부터 쓰는 구어체).

1. **배경**: 프로젝트, 저장소 경로, 지금 단계(마일스톤, 마지막 태그·커밋).
2. **고정 규칙**: [projects.md](projects.md)의 순서대로 찾아서 그대로 옮긴다. 그 파일 "공통" 절도 함께 옮긴다.
3. **할 일**: 체크리스트 번호와 확정 시안 항목(번호째, 시안 밖은 더하지 않음). 그림 시안이 있으면 그 파일이나 설명을 함께 넘긴다.
4. **하지 말 일**: 범위 밖 항목, `(사용자)` 표시 줄·사람 테스트(`T1` 등), 번호 바꾸기, 결제.
5. **끝난 모습**: 통과해야 할 확인 명령([test.md](test.md) "돌릴 테스트"), 체크리스트 ✅ 표시.
6. **git 범위**: 처음 질문에서 받은 답을 그대로 적는다(SKILL.md 2절). "파일만 고침"이면 "브랜치·커밋·push를 하지 말고 파일만 고친 뒤 바뀐 파일을 보고할 것"이라고 쓴다. "PR까지"면 [git.md](git.md)의 커밋 메시지 꼴과 PR 본문 꼴을 옮기고 "머지·태그는 하지 말 것"이라고 쓴다. 쓴 커밋 꼬리표 값도 적는다. 하위 세션은 브리프에 적힌 범위를 사용자 답으로 따르고 다시 묻지 않는다(SKILL.md 2절 "브리프로 시작한 세션"). 브리프에 없는 git 작업은 하위 세션도 하지 않는다.
7. **기다리는 법**: "백그라운드 작업 알림만 믿지 말고 결과 파일이나 프로세스 종료를 직접 확인할 것." 외부 서비스를 쓰는 일이면 "비밀값은 저장소에 넣지 않는다"와 사용자가 준 공개 값도 넣는다.
8. **보고 형식**: 마무리 메시지에 SKILL.md 8절의 네 칸(무엇을 바꿨나 · 어떻게 확인했나 · 범위 밖에서 건드린 것 · 확인 못 한 것·남은 것)을 적을 것.

직전 세션의 보고서나 대화를 통째로 넘기지 않는다. 필요한 사실만 요약한다(편향 방지).

## 시작하기

- `mcp__ccd_session__start_session`. 도구 목록에 이름만 있으면(deferred) 먼저 `ToolSearch`로 `select:mcp__ccd_session__start_session`을 불러온다. 이름만 있는 걸 안 보인다고 여겨 건너뛰지 않는다.
- context는 `"fresh"`(브리프가 전부 담는다), title은 "M2 저장 화면"처럼 무엇을 하는지 바로 보이게.
- git 범위가 "PR까지" 이상이면 `use_worktree: true`로 자기 작업 폴더(브랜치)에서 일하게 한다. "파일만 고침"과 "커밋까지"는 같은 폴더(지금 브랜치)에서 한 번에 하나씩 돌린다. 작업 폴더를 나누면 브랜치가 생기는데, 그 브랜치를 합칠 권한(PR·머지)을 받지 않았기 때문이다.
- 폴더마다 무거운 다시 가져오기·빌드가 필요한 프로젝트(게임 엔진 등)는 "PR까지" 이상이어도 기본 사본에서 하나씩 한다(`use_worktree: false`). 브리프에 "기본 브랜치에서 새 브랜치를 만들어 일하고, PR을 만든 뒤 기본 브랜치로 돌아갈 것"을 적는다.
- 서로 기대는 일은 앞 일이 끝난(PR이면 머지된) 뒤에 다음 세션을 시작한다.
- 모델은 SKILL.md 2절의 기본값(지금 세션과 같은 모델)이나 "내 방식"의 값을 쓴다.

## 새 세션을 만들 수 없으면

세션 도구가 아예 없거나(터미널 CLI, 웹) 앱이 시작을 막으면(휴대폰에서 보낸 말로 시작한 턴, 자동 알림 턴), 차례로 해 보고 되는 첫 길로 간다.

1. 쉬고 있는 기존 하위 세션에 `SendMessage`로 맡긴다(마일스톤 일이면 같은 마일스톤 세션만, `mcp__ccd_session_mgmt__list_sessions` `{"linked": true}`로 찾는다). 앞 일의 맥락에 기대지 말고 필요한 사실을 브리프에 다 적는다.
2. `Agent` 하위 에이전트에 맡긴다. git 범위가 "PR까지" 이상이면 `isolation: "worktree"`로. 하위 에이전트는 이번 턴에 끝나므로 줄마다 새로 맡기고 앞 줄의 결과를 요약해 넣는다.
3. 이 세션이 직접 한다.

보고 첫 줄에 어느 길로 갔는지 적는다. 자리 비움 중에도 이 순서로 계속한다.

## 기다리는 동안

- 폴링하지 않는다. 하위 세션이 턴을 끝내면 앱이 알려 준다.
- 하위 세션이 쉬는데 일이 안 끝났으면 `list_events`로 마지막 상태를 보고 `SendMessage`로 "결과 파일을 직접 확인하고 이어서 진행"하라고 보낸다.
- 하위 세션이 물으면 처음 질문의 답과 SKILL.md 5절로 답할 수 있으면 답한다. 사용자 몫인 결정만 사용자에게 묻고, 자리를 비웠으면 "돌아오시면 정할 것"에 모은다.

## 결과 확인

하위 세션의 보고는 증거가 아니다. 이 세션이 직접 본다.

1. **요약**: 보고(또는 PR 본문)의 네 칸이 다 찼나.
2. **시험**: CI가 있으면 CI 결과. 없으면 보고의 명령·종료 코드·결과 줄과 그 시험 코드를 읽는다. "통과했어요" 한 줄뿐이면 통과로 치지 않고 출력을 달라고 한다.
3. **범위**: 바뀐 파일이 브리프 범위 안이고 "하지 말 일"을 건드리지 않았나(`git status`·`git diff`, PR이면 파일 목록).
4. **합칠 수 있나**: PR이면 기본 브랜치와 충돌이 없나.

위험한 변경이면 [test.md](test.md) "위험한 변경 검토"를 한 번 더 한다. 하나라도 걸리면 그 세션에 `SendMessage`로 고치게 한다(새 세션을 만들지 않는다).

## 세션이 무거워졌을 때

하위 세션이나 이 세션의 대화 앞부분이 요약되기 시작하면 새 세션으로 넘긴다. 하위 세션이면 다음 줄을 새 세션에 맡기고 브리프에 끝난 줄만 요약해 적는다. 이 세션이면 이어 하기 메모를 고치고 사용자에게 새 세션을 제안한다([wrap-up.md](wrap-up.md) "요청할 때만 하는 것").
