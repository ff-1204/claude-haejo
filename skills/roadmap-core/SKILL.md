# roadmap-core — 핵심 경험과 범위

공통 규칙: [../roadmap/references/rules.md](../roadmap/references/rules.md)

## 모드

- **새로**: 핵심 경험과 범위가 아직 없을 때.
- **주제**: 한 주제 기획일 때(rules.md "기획 크기"). 제품 `personas.md` 머리의 핵심 경험·범위를 새 주제 폴더로 옮기고, 이 주제에서 바뀌는 것만 🔄로 고친다. 제품 문서가 없으면 저장소 문서에서 제품 핵심 경험을 먼저 정리한다.
- **바꾸기**: 이미 있는데 사용자가 바꾸려 할 때. 원래 목록은 지우지 않고 🔄로 표시하고, 빠진 것은 "(삭제)", 합친 것은 "(통합됨 → ②)".

## 입력

1. 사용자 말 (가장 우선)
2. 저장소의 콘셉트·기획 문서, README, CLAUDE.md
3. 이미 있는 `personas.md` 머리 (바꾸기 모드)

입력이 거의 없으면(빈 폴더, 한 줄 아이디어) 그 한 줄을 바탕으로 제안한다. 멈추지 않는다.

## 하는 일

1. **핵심 경험 3~6개**를 "사용자가 하는 일" 문장으로 쓴다. 기능 이름이 아니다.
   - 좋음: "친구가 만든 것을 받아 고쳐 쓴다"
   - 나쁨: "공유 기능", "리믹스 시스템"
   - 비슷한 제품에서 빌려 온 경험이면 괄호에 어떤 방식인지 짧게 적는다(예: "(블록 쌓기 게임처럼)"). 제품 이름을 써도 되는지는 프로젝트 규칙을 따른다.
2. **범위**를 세 줄로 쓴다: 대상 기기, 온라인 여부(혼자 / 같은 네트워크 / 인터넷), 지금 뺄 것.
3. 사용자 말이나 문서에 이미 정해진 것이 있으면 그대로 쓰고, 빈 곳만 제안으로 채운다.

## 출력

`personas.md`가 없으면 [../roadmap-personas/assets/personas.md](../roadmap-personas/assets/personas.md) 템플릿의 머리 부분만 채워 만든다(페르소나 본문은 비워 둠). 있으면 머리만 고친다. 제목의 인원 수(`N명`)와 "원래 있던 사람" 줄은 roadmap-personas가 채우므로 템플릿 글자 그대로 둔다.

```
> 갱신: YYYY-MM-DD HH:MM (핵심 경험·범위 정함)
> 근거: <읽은 문서, 사용자 말>
> 문서: personas.md · persona-scenarios.md · persona-checklist-map.md · <체크리스트> · roadmap.md
> 범위: <기기> · <온라인 여부> · <뺄 것>
>
> 핵심 경험: **① …** · **② …** · **③ …**
```

## 한 줄 보고

`⓪ roadmap-core: 핵심 경험 N개 · 범위 <요약> · personas.md`

상위 스킬이 이 뒤에 사용자 확인을 받는다. 혼자 불렸으면 목록을 보여 주고, rules.md "하위 스킬을 혼자 불렀을 때"의 한 줄을 붙여 끝낸다(묻지 않는다).
