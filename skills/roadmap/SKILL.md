# roadmap — 기획 플로우 상위 스킬

이 스킬은 직접 문서를 쓰지 않는다. 플로우를 고르고, 하위 스킬을 순서대로 부르고, 확인 지점에서 묻고, 마지막에 보고한다.

먼저 [references/rules.md](references/rules.md)를 읽는다. 문서 이름, 머리 줄, 번호, 묻는 법이 거기 있다.

## 1. 지금 상태 보기

1. `personas.md`의 `> 문서:` 줄로 문서 위치를 찾는다. 없으면 기본 위치(rules.md)를 쓴다. `**/personas.md`가 여럿이면 기획(제품 전체 + 주제마다)이 여럿이다. 아래 2~4를 **기획마다 따로** 보고, 상태 보고도 기획마다 한 덩어리로 낸다. `**/personas.md`가 여럿이면 기획(제품 전체 + 주제마다)이 여럿이다. 아래 2~4를 **기획마다 따로** 보고, 상태 보고도 기획마다 한 덩어리로 낸다.
2. 문서 다섯 개가 있는지, 각 문서의 `> 갱신:` 날짜·시각을 본다.
3. **낡음** 판단 (앞 단계가 뒤 단계보다 늦게 갱신됐으면 뒤 단계가 낡음):
   - personas → scenarios → map(매핑 문서 머리 `> 갱신:`) → score(1절 아래 `> 점수:`) → priority(3절 아래 `> 순서:`). 예전 꼴이라 `> 점수:`·`> 순서:` 줄이 없으면 매핑 머리 `> 갱신:`을 쓰고, 다음 실행 때 그 줄을 만든다.. 예전 꼴이라 `> 점수:`·`> 순서:` 줄이 없으면 매핑 머리 `> 갱신:`을 쓰고, 다음 실행 때 그 줄을 만든다.
   - `roadmap.md`는 **그 기획의 순서 줄(제품이면 `I00-00`, 한 주제면 `<절>-00`)의 날짜·시각이 `roadmap.md` 갱신보다 늦을 때만** 낡음이다. 순서를 바꾸지 않은 점수·우선순위 실행은 로드맵을 낡게 만들지 않는다.
4. 진행 상태: 마일스톤마다 세부 항목 ✅ 수 / 전체, 시나리오 ✅·🔜·일부만(한 줄에 둘 다 있는 단계, 따로 셈)·❌ 수.

## 2. 플로우 고르기

| 사용자 말 (예) | 플로우 | 하위 스킬 순서 (모드) |
|---|---|---|
| "처음부터 기획해줘", "페르소나부터 로드맵까지", "<주제>를 기획하고 개선해줘" | 전체 | core(새로) → personas(새로) → scenarios(새로) → map(전체) → score → priority(새로) → milestones(새로). 기획 크기(전체 / 한 주제)는 시작 질문에서 정한다(rules.md "기획 크기") |
| "페르소나 하나 더 추가해줘: <누구>", "이런 사용자도 넣어줘" | 더하기 | personas(더하기) → scenarios(더하기) → map(더해진 것만) → score → priority(바뀐 곳만) → milestones(바뀐 곳만) |
| "점수 다시 계산해줘", "우선순위 다시 봐줘" | 다시 보기 | score → priority(바뀐 곳만) → (순서가 바뀌었으면) milestones(바뀐 곳만) |
| "M2 끝났어", "시나리오 갱신해줘" | 갱신 | milestones(끝 표시) → scenarios(갱신) → score → priority(바뀐 곳만) → (순서가 바뀌었으면) milestones(바뀐 곳만) |
| "핵심 경험을 바꾸고 싶어" | 바탕 바꾸기 | core(바꾸기) → personas(다시 매김) → scenarios(갱신) → map(전체) → score → priority(바뀐 곳만) → milestones(바뀐 곳만) |
| "로드맵대로 개발해줘", "M2 진행해줘" | 개발 | 4절 "개발 플로우" |
| "로드맵 어디까지 왔어?" | 상태만 | 1절 결과 + 다음 세부 항목을 보고. 아무것도 고치지 않는다 |

- "전체"를 골랐는데 문서가 이미 있으면 처음부터 다시 쓰지 않는다. **낡은 단계부터** 이어 한다(한 주제를 고르면 이 줄 대신 새 주제 폴더에 처음부터). 처음부터 다시 쓰는 건 사용자가 그렇게 말했을 때만.
- 말이 애매하면 상태를 보고 가장 가까운 플로우를 고른다. 그래도 둘 이상이면 시작 질문(3절)에 플로우 선택을 넣는다.

## 3. 묻는 지점 (선택 UI, rules.md "묻기")

| 언제 | 무엇을 | 추천 |
|---|---|---|
| 시작 (전체·바탕 바꾸기만) | 기획 크기(전체 / 한 주제), 진행 방식(확인 지점마다 멈춤 / 알아서 끝까지 / 단계마다 멈춤), 문서 위치(공개 저장소면 "저장소 안 = 공개"라고 적음, rules.md "공개 저장소"), 페르소나 수, 커밋·push·태그 권한(항상 묻는다, rules.md "묻기") | 이미 돌아가는 프로젝트에 주제가 있으면 한 주제, 아니면 전체 · 확인 지점마다 멈춤 · 한 주제면 `docs/기획/<절>-<이름>/`, 전체면 저장소 루트 · 5명 |
| core 끝 | 핵심 경험 목록과 범위가 맞는지 | 제안한 그대로 |
| priority 끝 | 미루기 규칙(어려운 것·사람 확인 필요) 쓸지, 난이도 기준 | 둘 다 씀 · 기본 기준 |
| milestones 끝 | 마일스톤 수·경계, 사람 테스트 자리, 태그 | 제안한 그대로 |
| 끝 | 바로 개발로 갈지 | 다음 세부 항목부터 |

- 시작 질문에 이미 답이 있는 것(사용자 말, 메모리, 문서 머리)은 빼고 묻는다. 사용자의 첫 말에 "알아서 끝까지"가 있거나 사용자가 자리를 비웠으면(roadmap-teammate 10절) 시작 질문도 추천대로 정하고 보고에 적는다. 사용자의 첫 말에 "알아서 끝까지"가 있거나 사용자가 자리를 비웠으면(roadmap-teammate 10절) 시작 질문도 추천대로 정하고 보고에 적는다.
- "알아서 끝까지"면 core·priority·milestones 끝과 **마지막 질문까지 하지 않는다.** 추천대로 정하고, 개발은 시작하지 않는다(보고의 다음 할 일 1번으로 둔다). 마지막 보고에 "추천대로 정한 것" 목록을 붙인다.
- "단계마다 멈춤"이면 하위 스킬 하나가 끝날 때마다 한 줄 보고 후 계속할지 묻는다.
- 더하기·다시 보기·갱신 플로우는 시작 질문 없이 바로 돈다. 순서가 바뀌었을 때만 priority 끝 질문을 한다.

## 4. 하위 스킬 부르기

- `Skill` 도구로 `roadmap-<이름>`을 부르고 args에 모드와 필요한 값을 넣는다. 예: `Skill(roadmap-personas, "모드: 더하기 · 누구: 인터랙티브 무비를 만드는 영화 감독")`.
- Skill 도구에서 찾을 수 없으면 `~/.claude/skills/roadmap-<이름>/SKILL.md`를 읽고 그대로 따른다.
- 하위 스킬이 끝나면 한 줄 보고를 받아 사용자에게 그대로 전한다.
- 하위 스킬이 "입력 문서가 없다"며 멈추면 그 앞 단계를 먼저 부른다.
- 시나리오를 30명 넘게 새로 쓸 때는 roadmap-scenarios가 서브에이전트로 나눠 쓴다(그 스킬에 적혀 있다).

### 개발 플로우

1. **대상 마일스톤**: 사용자가 말한 것. 없으면 **✅가 아닌 세부 항목이 남은 첫 마일스톤**. 기획이 여럿이면(1절) 사용자가 고른 기획, 말하지 않았으면 **가장 최근에 만든 기획**(`personas.md` 첫 `> 갱신:`)을 쓰고 보고 첫 줄에 어느 기획인지 적는다. "M1"이 두 기획에 다 있고 하나가 이미 ✅면 아닌 쪽이다. 기획이 여럿이면(1절) 사용자가 고른 기획, 말하지 않았으면 **가장 최근에 만든 기획**(`personas.md` 첫 `> 갱신:`)을 쓰고 보고 첫 줄에 어느 기획인지 적는다. "M1"이 두 기획에 다 있고 하나가 이미 ✅면 아닌 쪽이다.
2. **세부 항목 고르기**: 그 마일스톤에서 ✅가 아닌 줄. `(사용자)` 표시가 있는 줄과 사람 테스트(`T1` 등)는 하위 세션에 보내지 않고 보고의 "사용자 몫"에 모은다.
3. **맡기기**: `roadmap-teammate` 스킬을 부른다. 세부 항목 한 줄 = 하위 세션 하나. 브리프에 넘길 것:
   - 그 줄의 체크리스트 번호와 "끝났다고 보는 것" → 할 일·끝난 모습
   - 그 번호를 가진 시나리오 단계들(누구의 몇 번 단계인지와 문장) → 하위 세션이 먼저 적을 여정
   - 마일스톤 이름과 태그 이름 → 배경
4. **마일스톤 끝**: 세부 항목이 모두 ✅면
   - 전체 검증을 한 번 한다(프로젝트 규칙의 전체 테스트, 여정 테스트). roadmap-teammate의 테스트 반복이 켜져 있으면 그 회차로 대신한다.
   - 갱신 플로우를 돈다(milestones 끝 표시 → scenarios 갱신 → score → priority).
   - 태그는 사용자 권한이다. 시작 질문에서 받은 권한대로만 달고, 없으면 그 자리에서 선택 UI로 묻는다.
   - 다음 마일스톤으로 넘어갈지는 roadmap-teammate 0절에서 정한 범위를 따른다.

## 5. 보고

- 하위 스킬마다 한 줄 보고를 이어 붙인다.
- 끝에:
  - 만든·바뀐 문서 (링크)
  - 🔜 상위 5개 묶음과 점수
  - 마일스톤 표 (이름 · 끝 기준 페르소나 · 세부 항목 ✅/전체)
  - 정한 것 / 추천대로 정한 것
  - 사용자 몫 (사람 테스트, `(사용자)` 줄)
  - 다음 할 일: 번호 붙은 선택지, 추천은 1번
- 커밋·push·태그는 시작 질문에서 받은 권한대로만 한다. 권한 없이 만든 변경은 커밋하지 않은 채 두고 보고에 적는다. 더하기·다시 보기·갱신처럼 시작 질문이 없는 플로우도 문서를 고친 뒤 커밋하려면 선택 UI로 묻는다.
