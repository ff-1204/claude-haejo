가상의 사용자 다섯 명의 하루에서 필요한 기능을 뽑고, 개발 단계표(마일스톤)까지 문서로 만들어요.

개발 맡기기

“M2 진행해줘”

일을 팀원(하위 세션)에게 하나씩 나눠 맡기고, 결과를 직접 확인한 뒤 보고해요.

정할 것만 묻기

팀처럼 일해요

PR

결재 서류

머지

결재 승인

바뀐 내용을 본 줄기(main)에 합쳐요.

  1. “M2 진행해줘”당신

  2. 권한을 버튼으로 묻기팀장

  3. 일마다 팀원 한 명팀장

  4. 자기 가지에서 만들고 테스트팀원

  5. 결재 서류(PR) 올리기팀원

  6. 네 가지 확인, 걸리면 다시팀장

  7. “머지할까요?”팀장

  8. “예” → 합치고 정리당신

보고만 믿지 않아요

다 통과해야
“머지할까요?”가 와요.

✓ 통과요약

바꾼 것·확인한 것·남은 것이 다 적혔나

✓ 통과테스트

팀장이 직접 한 번 더 돌려 보나

✓ 통과범위

맡긴 일 밖을 건드리지 않았나

✓ 통과충돌

다른 일과 부딪히지 않나

기획 흐름

씨앗에서 꽃까지, 일곱 걸음.

기능 목록이 아니라 사람에서 시작해요. 여러 사람에게 필요한 기능부터 만들어요.

1

핵심 경험

사용자가 하는 일 3~6개

2

페르소나

가상의 사용자 5명

3

하루 장면

한 사람의 하루 5~8단계

4

기능 잇기

장면마다 필요한 기능

5

점수

많이 필요할수록 높게

6

개발 순서

점수 순서를 다듬기

7

마일스톤

개발 단계 M1, M2…

점수 = 필요한 사람 수 × 2 + 나온 장면 수 · 눈대중이 아니라 프로그램(score.js)이 세요.

이렇게 말하세요

명령어는 외우지 않아도 돼요.

“처음부터 기획해줘”핵심 경험을 확인받고, 페르소나부터 마일스톤까지 써요.
“페르소나 하나 더 추가해줘”그 사람을 더하고, 뒤 문서에서 바뀐 곳만 고쳐요.
“M2 진행해줘”남은 일을 팀원에게 나눠 맡기고, 확인 뒤 머지할지 물어요.
“자러 갈게”떠나기 전 권한만 묻고 계속해요. 아침에 정할 것만 모아 둬요.
“로드맵 어디까지 왔어?”끝난 수와 다음 할 일만 알려 줘요.
